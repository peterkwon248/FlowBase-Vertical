세션을 닫는다. **작업한 것이 전부 GitHub에 올라간 상태**로 끝낸다.
다른 기기에서 `/before-work`로 그대로 이어받을 수 있어야 한다.

> 이 명령은 저장소 안(`.claude/commands/`)에 있다. 기기가 바뀌어도 clone하면 따라온다.

## 1. 지금이 정상인지 확인한다

프로젝트에 있는 것만 — 테스트·타입체크·린트·빌드.

**실패가 있으면 먼저 보고한다.** 고치고 닫을지, 깨진 채로 올릴지는 사용자가 정한다.
깨진 채 올려야 한다면 커밋 메시지에 그 사실과 이유를 남긴다.

## 2. 올릴 것을 고른다

```
git status --short
git diff --stat
```

- 각 변경을 왜 했는지 설명할 수 있어야 한다. 설명 못 하는 변경은 묻는다
- 임시 파일·디버그 스크립트·실험 흔적은 지운다
- **올리면 안 될 것이 섞였는지 본다** — 비밀키·토큰·개인정보·대용량 산출물.
  섞였으면 **커밋하지 말고 보고한다**. `.gitignore`에 추가할지 함께 정한다

## 3. 커밋한다

- 논리 단위로 나눈다. 관련 없는 변경을 한 커밋에 묶지 않는다
- 메시지에 **무엇을 왜**를 적는다. 특히 측정으로 뒤집힌 가정, 버린 접근과 그 이유,
  남은 한계
- 기본 브랜치에서 작업 중이었다면 — 브랜치를 팔지 그냥 올릴지 프로젝트 관례를 따른다.
  관례가 불분명하면 묻는다

## 4. 푸시한다

```
git push -u origin HEAD
```

- 실패하면 원인을 본다. **다른 기기에서 먼저 올려둔 게 있으면** 원격이 앞서 있다 —
  `/before-work`처럼 당겨와 합친 뒤 다시 올린다
- **force push는 하지 않는다.** 필요해 보이면 이유를 설명하고 사용자 확인을 받는다

## 5. PR — 올릴 게 있으면

기본 브랜치가 아닌 브랜치에서 작업했고 아직 PR이 없으면 만든다.

```
gh pr list --head <branch>        # 이미 있는지
gh pr create --fill               # 없으면
```

- `gh`가 없는 기기면(기기마다 다르다) compare URL을 만들어 알려준다:
  `https://github.com/<owner>/<repo>/compare/<base>...<branch>`
  설치를 권할 때는 그 기기의 패키지 관리자에 맞춰서 (`winget`·`brew`·`apt` 등)
- PR 본문에는 **무엇을 왜** 바꿨는지와 리뷰어가 봐야 할 곳을 적는다
- 기본 브랜치에 바로 커밋한 경우엔 PR이 없다 — 그게 정상이면 만들지 않는다

## 6. 인계 문서를 갱신한다

`docs/작업-상태.md`(없으면 프로젝트 관례에 맞는 이름). **저장소 안에 있어야 다른
기기로 따라온다.**

- 지금 어디인가 — 무엇이 통과했고 무엇이 아닌가
- 막혀 있는 것 — 사용자 작업이면 **실행할 명령까지**
- 다음 손이 갈 곳
- 새 기기에서 이어받는 법 — clone부터 테스트 통과까지, 필요한 런타임 버전
- **따라오지 않는 것** — gitignore된 것, 기기 로컬 상태(Claude 메모리·태스크 목록)

미완을 완료로 적지 않는다.

### 이 다섯을 특히 지킨다 (①~④는 2026-08-20에 넷 다 어긋났다)

> **★ 먼저 문장의 종류를 가른다 — ①과 ⑤가 여기서 나온다 ★**
>
> | | 예 | 낡나 |
> |---|---|---|
> | **규범 (should)** | 「Core는 마켓을 모른다」 · 「대사는 원본끼리만」 | ❌ **안 낡는다.** 코드가 어긋나면 코드가 틀린 것이다 |
> | **실측 주장 (is)** | 「결함 43건」 · 「`fact_ad_spend` 0행」 · 「미구현 화면」 | ✅ **쓰는 순간부터 낡는다. 예외 없다** |
>
> 2026-08-20 감사가 찾은 「코드보다 낡은 문서 16자리」도, 2026-08-21에 또 난 4건도
> **전부 is-문장이었다.** should는 한 줄도 안 깨졌다. 그러니 규율은 is에만 걸면 된다.

**① 숫자는 손으로 적지 않는다 — `npm run state`가 낸 것을 붙인다.**
손으로 적은 측정값은 굳는다. 클라우드 컨테이너에서 잰 「스키마 13」과 「리스팅 190건
미연결」이 데스크톱의 사실인 척 인용됐고, 실측은 11과 「미연결 0」이었다.
기기마다 다른 값을 문서가 단정하면 다음 세션이 그걸 믿는다.

> ⚠ **이 규칙은 인계 문서에만 걸려 있었다. 그래서 2026-08-21에 또 났다.**
> 「`fact_ad_spend`가 실 DB·데모 둘 다 0행이다 → 광고비 탭은 만들어도 빈 화면」이
> `docs/코드-남은일`에 적혀 있었고 그 사유로 순서가 뒤로 밀렸는데, 실측은
> **80,137행 · 15,700,534원**이었다. `npm run state`가 그 값을 이미 출력하고
> 있었는데도 그랬다 — 규율이 **문서 하나에만** 걸려 있었기 때문이다.
> **①은 모든 문서에 적용된다.** ADR·조사 문서·주석도 예외가 아니다.

**② 미룬 것은 미루는 자리에 적는다.**
ADR-019가 「기준 가져오기의 기록 화면 표출은 **대기 목록으로 남긴다**」고 약속했는데
`docs/다음-마이그레이션-대기목록.md`에 그 항목이 없었다. 미뤘는데 미뤄둔 자리에 안
적혔고, 그래서 열흘을 떠 있었다. **「나중에」라고 썼으면 그 「나중에」가 사는 파일에
같은 커밋으로 넣는다.**

**③ 사용자가 설계를 말했으면 그 세션 안에 ADR로 만든다.**
상태 문서의 요약이 원본을 대체하지 않는다. 같은 「다음 손」 목록에 있던 두 항목 중
ADR을 받은 「묶음」은 구현까지 갔고, 두 줄로 남은 「원본 보관층」은 다음 세션이
알아보지 못했다. **결정 강도까지 안 올라간 아이디어는 한 줄만큼만 전달된다.**

**④ 「다음 손」은 사용자가 화면에서 확인할 수 있는 것부터 고른다.**
내부 정리·리팩터·게이트가 아무리 옳아도 앞에 두지 않는다 — 사용자가 눈으로 변화를
못 보면 흥미도 의욕도 안 생긴다(2026-08-20 사용자 본인의 말). 화면에 안 보이는 일을
1순위로 적어야 한다면 **왜 그것이 먼저인지**를 그 자리에 적는다.

**⑤ is-문장에는 «언제 · 어디서 · 무슨 명령으로» 잰 것인지 붙인다. 못 붙이면 안 적는다.**

`npm run state`의 출력은 `실측 — 2026-08-21 09:13 · node v24.13.0 · win32` 머리를
달고 나온다. 그런데 문서로 옮겨 적히는 순간 **그 머리가 떨어지고 보편 사실인 척한다.**
「0행」은 쓰인 그 순간엔 참이었을 것이다 — 그 기기의 그 DB에서. 틀린 것은 숫자가
아니라 **출처를 뗀 문장 형태**다.

```
✗  fact_ad_spend는 실 DB·데모 둘 다 0행이다
✓  fact_ad_spend 0행 (2026-08-20 · 클라우드 컨테이너 · npm run state)
✓  광고 행 수는 `npm run state`로 잰다 — 기기마다 다르다
```

★ **기기 로컬 상태는 숫자를 아예 적지 않는다** ★ `.tmp/pnl.sqlite`의 내용(행 수·
SKU·연결·묶음)은 **gitignore라 기기마다 다르고 CI가 영원히 못 잰다.** 사용자가 앱으로
넣은 것은 `pnl.ts`가 재현하지도 못한다. 그러니 이 부류는 **숫자 대신 재는 명령**을
적는다 — `docs/사용자-불변식.md`의 「지킬 수 없는 문장은 여기 안 적는다」와 같은 규율이고,
검증할 수 없는 주장을 **안 쓰는 것**이 유일하게 성립하는 처방이다.

## 7. 닫혔는지 확인하고 보고한다

```
git status -sb                        # 깨끗하고 원격과 같은가
git log --oneline origin/HEAD..HEAD   # 비어 있어야 한다
```

**여기까지 통과해야 "닫혔다"고 말한다.** 다른 기기에서 이어받을 사람이 있으므로,
올렸다고 착각하고 끝내면 그 기기에서 작업이 사라진 것처럼 보인다.

보고: 무엇이 올라갔나 · PR 링크(있으면) · 무엇이 열려 있나 ·
사용자가 해야 할 일(명령과 함께).

## 규칙

- **기기 로컬 상태는 따라오지 않는다.** Claude 메모리(`~/.claude/…`)·태스크 목록·
  gitignore된 파일은 다음 기기에 없다. 이어가는 데 필요한 것은 전부 저장소 안 문서로 옮긴다
- 측정으로 판정하는 기준은 **분포를 본다.** 한 번 통과한 수치를 합격으로 적지 않는다
- 사용자가 "닫아줘"라고 했다고 해서 깨진 것을 조용히 올리지 않는다
