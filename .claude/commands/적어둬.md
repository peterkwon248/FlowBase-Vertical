description: 대화에서 나온 할 일·결정·결함을 저장소의 «제자리»에 적는다 (세션 중간에)
---

방금 대화에서 나온 것을 **저장소 안 제자리에 적는다.** 세션이 끊겨도, 기기가 바뀌어도
`/before-work`가 그것을 읽는다.

```
/적어둬 <내용>          내용을 적으면 그것을
/적어둬                 인자가 없으면 «방금 대화에서 나온 것»을 내가 골라 제안한다
```

> 이 명령은 저장소 안(`.claude/commands/`)에 있다. 기기가 바뀌어도 clone하면 따라온다.

---

## 왜 있나 (2026-08-20)

`/after-work` 6단계가 인계 문서를 갱신하지만 **그건 세션 끝에만 돈다.** 대화 중간에
나온 것은 그때까지 아무 데도 안 남고, 세션이 길어지거나 끊기면 사라진다.

같은 날 세 번 새어나갔다:

1. **「원본 보관층」** — 사용자가 말한 설계가 상태 문서에 **두 줄**로만 남았다.
   같은 목록의 「묶음」은 ADR-021을 받아 3커밋 만에 화면에 섰고, 이건 열흘을 떠 있었다
2. **ADR-019의 「대기 목록으로 남긴다」** — 약속만 하고 **그 목록에 안 적었다.** 두 번 잊혔다
3. **조사 47건** — 임시 파일에만 있었다. 요약 6줄만 문서로 갔다

> **결정 강도까지 안 올라간 것은 딱 한 줄만큼만 전달된다.**

## 1. 무엇인지 판정한다 — **새 파일을 만들지 않는다**

이 저장소의 병은 「적을 곳이 없다」가 아니라 **「적을 곳이 흩어져 있다」**였다.
(2026-08-20 감사: 「다음 손」이 10곳에 흩어져 각자 다른 「다음」을 가리켰다.)

**그러니 새 파일을 만들지 말고 아래 표로 보낸다.** 어디에도 안 맞으면 **묻는다.**

| 이것이면 | 여기에 적는다 |
|---|---|
| **왜 이렇게 하기로 했나** (설계·방향·번복) | **새 ADR** — `docs/ADR-템플릿.md`에서 시작. ★ 「파급면」 절을 반드시 채운다 |
| **스키마가 느는 일** (표·컬럼·뷰) | [`docs/다음-마이그레이션-대기목록.md`](../../docs/다음-마이그레이션-대기목록.md) |
| **화면이 목업과 다르거나 결함** | [`docs/목업-결함-발견분.md`](../../docs/목업-결함-발견분.md) — 번호를 잇는다 |
| **코드에 남은 일** (배선·조항 미이행·게이트) | `docs/코드-남은일-*.md` — 있으면 거기, 없으면 만들되 **한시 문서**로 표시 |
| **사용자만 할 수 있는 일** (실기기·판단·실물 파일) | [`docs/작업-상태.md`](../../docs/작업-상태.md) 「사용자만 할 수 있는 것」 — **실행할 명령까지** |
| **다음에 손댈 곳** | `docs/작업-상태.md`의 **「다음 손」 절 하나뿐** — 다른 곳에 쓰지 않는다 |
| **어떻게 일하는가** (규율) | [`docs/작업-리듬.md`](../../docs/작업-리듬.md) |
| **명령어가 대신 지켜야 할 규율** | `.claude/commands/*.md` — 규율은 「하자」로는 안 지켜지고 **한 줄로만** 지켜진다 |

### 판정이 애매하면 — 둘 다 아니라 **한 곳 + 링크**

여러 곳에 걸치면 **본체는 한 곳**에 적고 나머지는 **링크 한 줄**만 둔다.
같은 내용을 두 곳에 적으면 하나가 반드시 낡는다.

## 2. 적을 때 반드시 넣는 것

한 줄짜리 메모는 **한 줄만큼만 전달된다.** 다음 사람이 그것만 읽고 손댈 수 있어야 한다:

- **무엇이 왜 아픈가** — 「느낌상」이 아니라 **실측**. *"80,138행에서 9.3초"*
- **어디** — `파일:줄`. 없으면 지금 찾아서 붙인다
- **크기** — S(한 파일 몇 줄) · M(여러 파일) · L(스키마·설계가 는다)
- **눈에 보이나** — 사용자가 화면에서 확인할 수 있는가 (`/after-work` 6-④의 정렬 기준)
- **막고 있는 것** — 선행 조건이 있으면
- **끝나면 지울 자리** — 래칫·주석·문서 어디를 함께 고쳐야 하는가

### 「나중에 한다」고 적었으면 **그 「나중에」가 사는 파일에 같은 손으로 넣는다**

ADR-019가 「대기 목록으로 남긴다」고 쓰고 **그 목록에 안 넣어서** 열흘 떠 있었다.
약속을 적은 자리와 약속이 사는 자리는 다르다. 둘 다 적는다.

### 사용자가 **설계**를 말했으면 요약으로 끝내지 않는다

두 줄 요약은 다음 세션이 못 알아본다. **그 자리에서 ADR 초안까지 만든다.**
확인 못 받은 부분은 상태를 **「제안 · 사용자 확인 대기」**로 두고 **확인 질문을 문서 끝에 남긴다** —
없는 합의를 채택으로 적지 않는다.

## 3. 적은 뒤

- **커밋하지 않는다.** `/after-work`가 가져간다 — 다만 **지금 커밋할지 사용자에게 묻는다**
  (세션이 길어질 것 같으면 지금 커밋하는 편이 안전하다)
- 무엇을 **어디에** 적었는지 한 줄로 보고한다. 링크까지
- **인계 문서의 「다음 손」과 충돌하는지** 본다. 순서가 바뀌면 그것도 함께 고친다

## 규칙

- **새 파일을 만들지 않는다.** 위 표 밖이면 묻는다 — 흩어지는 것이 이 저장소가 앓았던 병이다
- **미완을 완료로 적지 않는다**
- **확인 안 받은 것을 결정으로 적지 않는다.** 「제안 · 확인 대기」가 정직한 상태다
- 숫자를 적을 때는 **`npm run state`로 재고 적는다.** 기기가 다르면 숫자도 다르다
