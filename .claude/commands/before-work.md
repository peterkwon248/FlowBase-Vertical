description: 작업 시작 — 원격을 당겨와 이어갈 수 있는 상태로 만든다
---

작업을 이어간다. **원격을 당겨오고, 돌아가는지 확인하고, 어디서부터인지 말한다.**

> 이 명령은 저장소 안(`.claude/commands/`)에 있다. 기기가 바뀌어도 clone하면 따라온다 —
> 데스크톱·노트북·핸드폰 어디서 열어도 같은 명령이 뜬다.

## 1. 당겨온다

```
git status --short
git fetch --all --prune
git status -sb
```

상황별로:

- **작업 트리가 더러우면** — 먼저 무엇이 왜 남아 있는지 보고한다. 다른 기기에서
  `/after-work` 없이 끊긴 흔적일 수 있다. 사용자 확인 없이 stash·reset·checkout으로
  지우지 않는다
- **깨끗하면** — `git pull --ff-only`. fast-forward면 그걸로 끝이다
- **갈라졌으면**(로컬에도 원격에도 커밋이 있음) — **자동으로 rebase/merge 하지 않는다.**
  기기를 오가며 작업하면 흔히 생기는 상황이다. 양쪽 커밋을 보여주고 어떻게 합칠지 묻는다
- **로컬에 안 올라간 커밋이 있으면** — 짚어준다. 이전 기기의 `/after-work`가 끝나지 못한 것이다

## 2. 당겨온 것을 반영한다

```
git log --oneline HEAD@{1}..HEAD    # 이번 pull로 들어온 것
```

- 잠금 파일(`package-lock.json` 등)이 바뀌었으면 **재현 설치**를 돌린다
  (`npm ci`. `npm install`이 아니다)
- 마이그레이션·스키마 변경이 들어왔으면 적용이 필요한지 확인한다
- **기기가 처음이면** 의존성이 아예 없다 — 그때도 재현 설치부터

## 3. 지금이 정상인지 확인한다

프로젝트에 있는 것만 — 테스트·타입체크·빌드.

**실패가 나오면 그것부터 보고한다.** 깨진 위에 새 작업을 쌓으면 원인이 섞인다.
런타임 버전이 기기마다 다를 수 있으니, 실패가 환경 탓으로 보이면 버전부터 확인한다.

## 4. 어디서부터인지 말한다

인계 문서를 읽는다 — `docs/작업-상태.md` · `CLAUDE.md`.
없으면 최근 커밋 10개로 대신하고, 없다는 사실을 보고한다.

그리고 짧게:

1. **당겨온 것** — 원격에서 뭐가 들어왔나 (없으면 "최신")
2. **지금 어디인가** — 어느 단계까지 됐나
3. **막혀 있는 것** — 사용자가 풀어야 할 게 있으면 명령까지
4. **다음 손이 갈 곳** — 하나를 고르고 이유 한 줄

## 규칙

- **파괴적 git 명령을 먼저 쓰지 않는다.** `reset --hard` · `checkout --` · `clean` ·
  force pull은 사용자가 명시적으로 요청할 때만
- 인계 문서에 적힌 전제(경로·버전·설정값)도 **실측으로 확인**한 뒤 인용한다.
  다른 기기에서 쓴 문서라 이 기기와 다를 수 있다
- 파악이 끝나기 전에 코드를 고치지 않는다
