# ADR-016 — 원가 대기 스테이징: 못 붙은 원가를 버리지 않는다

날짜: 2026-08-19 · 상태: 확정 · 관련: [ADR-005](ADR-005-기준데이터-이력-범위.md) · [ADR-006](ADR-006-source-key-전략.md) · [§20](§20-보강-확인-질문.md) 규칙 3·4

## 문제 — 실측

사용자의 실제 단가표(카드 레이아웃 · 13MB · 15시트)를 블록 리더가 200블록 전부
읽어냈는데 **0건이 붙었다.** 파일에 마켓 상품번호가 한 개도 없어서다 — 다리
(`listingKeyColumn`)는 `listing_key` 정확 일치인데 품명은 키가 아니라 제목이다.

그때 `run-reference`는 못 찾은 행의 품명·모델명·금액·적용일을 **버렸다** — 남는
것은 개수와 표본 키 ≤10뿐. 사람이 나중에 «이 품명 = 이 상품»을 판단할 재료가
증발한다. 이름 유사도 실측(강함 ≥50% 129 / 200)은 그 판단이 실제로 가능함을
보여주는데, 재료가 없으면 판단할 대상이 없다.

## 결정 — `pending_cost` (마이그레이션 011)

`file_sighting`(009)이 「봤다 → 남는다」로 뒤집은 순서를 원가에 적용한다:
**못 붙었다 → 남는다 → 사람이 잇는다.**

### 분류: Fact도 이력도 아닌 메타다

- Fact가 아니다 — 공통 6컬럼도 `row_shadow`도 없다. 되돌리기 대상이 아니다.
- 이력이 아니다 — ADR-005의 이력은 **확정된** 원가의 것이고 이건 확정 전이다.
- 그래서 B-5(원가 저장소 하나)와 충돌하지 않는다: 유효값 계산(`costAt`·손익)은
  여전히 `cost_history`만 읽고, `pending_cost`는 계산 밖이다.
  `tests/pending-cost.test.ts`가 «대기실은 손익에 안 들어간다»를 고정한다.

### UPSERT 키 = (library_id, kind, source_key)

`source_key`는 프로파일의 `sourceKey` 선언(ADR-006)으로 만든다 — 대기 행의
정체성 규칙을 새로 발명하지 않는다. 결과:

- 같은 파일 재가져오기 → 행 불변, 값(amount·effective_from)만 최신 (실측: 175행 유지)
- **같은 품명이 두 시트에 실린 상품은 한 행으로 합쳐진다** (실측 1건 — 176 stash
  → 175행). 같은 물건이 카테고리 시트 두 곳에 실린 것이므로 합쳐지는 것이 맞다
- 상태(resolved·dismissed)는 재가져오기가 **덮지 않는다** — 판단이 재가져오기
  한 번에 초기화되면 판단이 아니라 메모다

### ★ resolved 행이 곧 다리 사전이다 ★

사람이 「품명 X = SKU Y」를 한 번 확정하면(`resolvePendingCost` — addCost와 상태
갱신이 **한 트랜잭션**), 다음에 같은 `source_key`가 오면 `run-reference`가 그
SKU로 곧장 넣는다(`bridged`로 따로 센다). 점수 자동 확정이 아니라 **과거의 사람
판단 재사용**이다 — §20 규칙 4(「답 = 갱신, 다음 파일부터 질문 0」)의 원가판.
리포지토리 쓰기 함수가 점수를 인자로 받지 않는 구조는 그대로다.

`dismissed`는 삭제가 아니라 세고 있는 부재다(§20 규칙 3) — 화면이 «무시한 N건»을
셀 수 있고, 거둘 수 있다. resolved의 되돌리기는 v1 밖이다(확정된 원가 이력을
지우는 별개 문제).

### 못 읽은 행은 대기실에 못 간다

금액을 못 읽은 행(`badRows` — 실측 24건: 「13,300 (60元)」·「19500 > 12,000」)은
stash하지 않는다 — 금액 없는 대기 행은 확정 시 금액을 다시 물어야 하고, 그건
지어내기 아니면 재질문이다. badRows로 세어서 말하는 것이 현재의 정직한 처리다.

## 실측 (2026-08-19, 사용자 실파일 + 데모 DB)

```
1차 가져오기   stashed 176 · bridged 0 · badRows 24   (블록 200 = 176 + 24)
대기실        175행 (품명 중복 1건 합쳐짐) · 모델명 있는 행 156
2차 (멱등)    행 수 불변
확정 1건 후    bridged 1 · stashed 175 — 지난 판단이 재사용된다
```
