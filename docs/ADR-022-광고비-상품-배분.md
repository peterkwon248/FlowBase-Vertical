# ADR-022 — 광고비를 상품까지 내린다

날짜: 2026-08-20 · 상태: **채택 · 구현됨** (마이그레이션 014)
관련: ADR-004 · ADR-009 · §22 · LOCK 4 · LOCK 6 · 감사 A-1-1

---

## 문제

`profit/snapshot.ts`가 **`adDirect: 0`을 리터럴로** 넣고 있었다.

```ts
adDirect: 0,
adUnallocated: adSpend,
```

게으름이 아니었다. **저장 계층이 표현할 수 없었다** — `fact_ad_spend`는 캠페인 단위
표라 「이 광고비가 어느 상품 것인가」를 담을 칸이 아예 없었다.

그 결과 광고비 **전액**이 2층(미배분)으로 갔고 **1층과 2층의 경계가 통째로 틀렸다.**
「이 상품이 남는가」의 답이 낙관적인 쪽으로 틀린다 — 상품별 손익이 광고비를 한 푼도
지지 않는다.

**3층(회사 순이익)은 합이라 맞다.** 총액만 보면 아무 이상이 없어 보인다.
그게 이 결함이 오래 산 이유다.

## 조사 — 붙을 수 있나, 얼마나

배분 규칙을 **발명하기 전에** 파일이 이미 말하고 있는지부터 셌다.

```
쿠팡 광고 보고서 80,137행 · 광고비 15,700,534원 · 고유 「광고집행 옵션ID」 65개

  쿠팡 제트 매출의 「옵션ID」와 대조    20개 일치 · 14,955,098원   ★ 95.3% ★
  쿠팡 일반 매출의 「옵션ID」와 대조    19개 일치 ·    719,101원       4.6%
  「노출상품ID」로 대조                 0개 일치 — 층위가 다르다 (상품 vs 옵션)
  11번가 기간별보고서 (#2·#11)         상품 열이 아예 없다 — 일자별 집계다
```

**배분 규칙이 필요 없다.** 파일이 «이 광고는 이 옵션의 것»이라고 직접 말한다.
안분·가중치 같은 것을 지어내면 그건 우리가 만든 숫자이지 사실이 아니다.

### 버린 접근

| 접근 | 왜 버렸나 |
|---|---|
| 캠페인명에서 상품명 문자열 매칭 | 「광고집행 옵션ID」라는 **정확한 키가 이미 있다.** 유사도 매칭은 키가 없을 때의 수단이다 |
| 전환매출 비율로 안분 | **비용의 임자가 바뀐다.** A 광고를 보고 B를 샀다고 B가 A의 광고비를 지는 것이 아니다 |
| 「광고전환매출발생 옵션ID」를 쓴다 | 같은 이유. 그 열은 «무엇이 팔렸나»이고 비용의 임자는 «어디에 걸었나»다 |
| 매출 비율로 전액 안분 | 상품 손익이 **광고를 한 적 없는 상품에도** 광고비를 지운다. 조용한 왜곡 |

## 결정

`fact_ad_spend`에 **`listing_key`** 한 칸을 연다 (014). 있으면 리스팅→SKU로 이어
**직접 광고비**(1층), 못 이으면 **미배분**(2층).

```
직접   listing_key 있음 → 리스팅 있음 → link_state='linked' → sku_id 있음
미배분 그 밖 전부 — 그런데 «그 밖»이 한 가지가 아니다
```

### ★ 미배분을 세 갈래로 센다 — 처방이 다르다 ★

| 갈래 | 뜻 | 사용자가 할 일 |
|---|---|---|
| `noLink` | 리스팅은 찾았는데 SKU 미연결 | **연결한다** — 과거 광고비까지 소급해 붙는다 |
| `noListing` | 그 옵션의 주문 파일이 아직 없다 | 그 기간 주문 파일을 넣는다 |
| `noKey` | 파일이 상품을 안 말한다 | **없다** — 채널 단위로만 볼 수 있다 |

한 덩어리로 «미배분 15,700,534원»만 보이면 사용자는 **할 수 있는 일이 무엇인지
모른다.** 실측에서 그 95%가 「연결만 하면 붙는」 돈이었다 — 막힌 것이 아니라 한
동작 남은 것이다. `cogs-unlinked`와 `cogs-missing`을 가른 것과 같은 판단이다.

## ★ 파급면 — 이 결정이 닿는 표면 전수 ★

### 무엇이 함께 움직이나

| 층 | 닿나 | 무엇 |
|---|---|---|
| 스키마 | ✅ | `fact_ad_spend.listing_key` · `idx_ad_listing` · **`shadow_fact_ad_spend` 재생성** |
| 조회 | ✅ | `snapshot.ts`가 `active_ad_spend ⋈ marketplace_listing`. 연결은 **조회 때** 잇는다 (`ITEM_JOIN`과 같은 판단 — 적재 때 박으면 소급이 안 된다) |
| 화면 | ✅ | `PnlSnapshot.adSplit` 신설 · `gaps.ts`에 단서 3종 · `FIELD_LABEL`에 「광고 건 상품」 |
| 도구 | ✅ | `pnl.ts`가 쿠팡 주문(#15)도 넣는다 — 안 그러면 새 코드가 개발 DB에서 **한 번도 안 돈다** |
| 게이트 | ✅ | `ad-allocation` 신설 · `shadow-columns` 신설 · `batch-rows`(라벨 전수)가 자동으로 물었다 |

### ★ LOCK 재적용 ★

| LOCK | 판정 |
|---|---|
| 1 Fact 공통 6컬럼 | 건드리지 않음 — 새 컬럼은 공통이 아니라 광고 전용 |
| 2 append-only | ✅ batch 의미론 그대로. UPSERT 정체성(`connection_id`,`source_key`) 불변 |
| 3 원본 불변 | ✅ 배분은 **조회 때** 계산한다. 적재된 값을 고치지 않는다 |
| 4 Core는 마켓을 모른다 | ✅ 컬럼명은 `listing_key`. 「옵션ID」는 팩의 프로파일이 번역한다 |
| 5 메모리 적재 금지 | ✅ 집계는 SQL. `idx_ad_listing`이 조인을 받는다 |
| **6 조용한 실패 금지** | ★ **여기가 핵심이다.** NULL은 «0»이 아니라 «모름»이다. 세 갈래를 따로 세고 화면이 각각 다른 처방을 말한다 |
| 7 AI는 선택 | 무관 |
| 8 내보내기 개방 | 무관 |
| 9 인라인 편집 금지 | ✅ 새 편집 표면 없음 |
| 10 「동기화」 카피 금지 | ✅ 새 카피에 없음 |

### 사용자 불변식 재적용

- **U-5 (저장 분류 ≠ 화면 언어)** — 화면 라벨은 「광고 건 상품」이다. `listing_key`가
  사용자 문장에 나오지 않는다.
- **U-7 (모르는 것을 아는 척 안 한다)** — `noKey`를 «0원»으로 그리지 않는다.
  「파일이 안 말함」이라는 **상태**로 그린다.
- **U-6 (숫자는 근거를 말한다)** — 미배분 금액이 세 갈래 중 어디서 왔는지 말한다.

### 앞선 결정을 뒤집나

**뒤집지 않는다.** ADR-009(손익 3층)의 정의 그대로이고, 이 결정은 그 정의를
**처음으로 참이 되게** 만든다. 다만 **ADR-004(되돌리기)에 새 의무가 생겼다**:

- [x] `shadow_fact_ad_spend`를 014에서 **다시 만들었다.** 002의 트리거는 컬럼을
      하나씩 나열하고 SQLite는 트리거 본문을 텍스트로 보관하므로, 컬럼만 늘리면
      되돌리기가 `listing_key`를 **NULL로 복원한다** — 조용한 값 손실이다.
- [x] 같은 사고가 다음 컬럼에서 또 나지 않도록 `tests/shadow-columns.test.ts`로
      **전수 검사**를 세웠다 (표의 모든 컬럼이 트리거에 있는가 · `'X', OLD.X` 짝이
      어긋나지 않는가). 이 시험을 쓰다가 **내가 낸 오타**(`'conversions', OLD.conversion_amount`)를
      잡았다.

## 따름 조건

1. `adDirect + adUnallocated == 총 광고비`. **뺄셈으로 구한다** — 세 갈래를 더해
   만들면 하나를 빠뜨렸을 때 총 광고비가 조용히 줄어든다.
2. `noKey + noListing + noLink == adUnallocated`. 미배분의 이유가 미배분을 **빠짐없이
   덮는다.** 새면 설명되지 않는 광고비가 생긴다.
3. 조인에 `link_state`를 걸지 않는다. 걸면 **미연결 리스팅이 「리스팅 없음」으로
   세어진다** — 처방이 완전히 다른 두 상태가 한 칸에 섞인다. (첫 판이 그랬고
   시험이 `noListing 8,000`으로 잡았다)

셋 다 `tests/ad-allocation.test.ts`가 지킨다.

## 재검토 트리거

- **상품 식별자를 주지 않는 광고 파일이 주력이 되는 날** — 지금은 11번가 기간별
  보고서가 그렇고 실측 `noKey`는 0원이다. 이게 커지면 「채널 단위로만 본다」가
  기본 동작이어야 할 수도 있다.
- **한 광고 행이 여러 상품에 걸리는 양식이 오는 날** — 지금 전제는 «행 하나 = 상품
  하나»다. 그때는 안분이 불가피해지고, 그 순간 이 ADR을 다시 연다.
- **`noLink`가 오래 안 줄어드는 날** — 연결이 병목이라는 뜻이고, 그건 광고 문제가
  아니라 상품 연결 화면의 문제다.

## 예약한 측정

없다. 판정에 필요한 실측은 **결정 전에** 끝냈다 (위 「조사」).

구현 후 실측 (개발 DB · 2026-07):

```
직접 광고비 (1층)                    0원
미배분     (2층)           15,700,534원
  ├ 파일이 상품을 안 말함              0원
  ├ 주문 파일이 아직 없음        745,436원
  └ 연결만 하면 붙는다        14,955,098원   ★ 95.3%
```

파일 대조로 **미리 계산한 14,955,098원과 원 단위로 일치한다** — 파이프라인이
독립적으로 같은 답을 냈다. 리스팅 147개가 전부 미연결이라 오늘 직접 광고비는
0이고, **그게 옳은 동작이다**: 연결 전에는 어느 SKU 것인지 앱이 모른다.
