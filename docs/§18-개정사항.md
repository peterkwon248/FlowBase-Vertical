# §18 개정사항 — 파이프라인 구현에서 나온 UI 요구

헌장 C-5는 §18의 구현 항목 5가지를 지정했다(멀티시트 시트 선택 · 제외 행 삭선+카운트 ·
판정 후보 복수+일치도 · 파일 정체 고지 · 대용량 진행). 파이프라인을 실제로 만들면서
**그 목록에 없던 요구**가 나왔다.

**기록은 지금, 구현은 세션 3.** 새 시각 요소를 발명하지 않는다 — 기존 위저드 패턴 안에서
문구와 배지로 해결한다(헌장 C-5·E-1).

---

## 18-A. 수식 비율 경고 — 파생 데이터를 사실로 적재하는 사고 방지

### 무엇

시트 선택 단계에서, 수식 비율이 높은 시트를 **사실(Fact) 대상으로** 고르려 할 때 한 줄 경고.

> 이 시트는 96%가 수식으로 계산된 값입니다 — 원본 데이터가 따로 있다면 그쪽이 안전합니다.

### 왜

세션 1 실측: 픽스처 #3의 `통합_상품분석`은 셀의 99%가 수식이고, `이베이`·`11번가`·`B2B`도
96~98%다. 이들은 다른 시트에서 계산된 값이다.

파생 시트를 사실로 적재하면 **같은 매출이 두 번 계산된다.** 원본 시트와 그 요약 시트를
둘 다 가져오면 합계가 두 배가 되는데, 화면에는 그냥 큰 숫자로 보인다 — 헌장 A-5가
"최악의 버그"라 부른 조용히 틀린 숫자다.

자동으로 막을 수는 없다. 수식 비율은 파생 여부를 **가르지 못한다** — `이베이`(96%, 원본)와
`통합_상품분석`(99%, 파생)이 같은 구간에 있다 (ADR-002 §4). 그래서 차단이 아니라
**고지**다. 판단 재료를 사람 앞에 놓는다.

### 데이터는 이미 있다

`SheetInfo.formulaRatio`가 세션 1에서 구현됐다 (0..1, 알 수 없으면 `null`).
`fixtures/manifest/manifest.json`에도 시트별로 들어 있다.

### 규칙

- 임계값은 **경고 표시 여부에만** 쓴다. 역할 판정에는 쓰지 않는다
- 사용자를 막지 않는다 — 고르겠다면 고를 수 있다. 다크패턴 금지(지시서 §3-A와 같은 톤)
- `formulaRatio === null`(구분자 텍스트·fast path 등 셀 수 없는 경로)이면 경고하지 않는다.
  모르는 것을 아는 척하지 않는다

## 18-B. 시트 선택은 최종 게이트다 — 건너뛰기 금지

### 무엇

멀티시트 파일에서 시트 선택 단계를 "전부 선택 후 다음"으로 자동 통과시키지 않는다.
자동 판정 결과는 **체크 상태의 초안**으로 제시하고, 확정은 사람이 누른다.

### 왜

세션 1이 이 화면의 존재 이유를 실증했다. #3에서 이름 힌트를 끄면 19시트가 전부
`data`로 나오고, 수식 비율로도 갈리지 않는다. **파일 안에 정답이 없다** — 어느 시트가
원본이고 어느 것이 파생인지는 작성자만 안다 (ADR-002 §4).

즉 이 화면은 편의 기능이 아니라 자동 판정이 원리적으로 닿을 수 없는 지점을 메우는
장치다. 건너뛰게 만들면 그 지점이 그냥 비게 된다.

### 규칙

- 판정 사유를 함께 보인다 — `SheetInfo.reason`이 이미 사람이 읽을 문장으로 들어 있다
  (예: `시트명에 "분석" — 사람이 붙인 파생 선언으로 본다 (헤더 확신 0.97, 직사각형도 1.00, 데이터 행 146, 수식 99%)`)
- 단일 시트 파일에는 이 단계를 띄우지 않는다 — 고를 게 없다

## 18-C. "데이터 후보 · 0행"을 요약과 다르게 보인다

### 무엇

구조는 표인데 이번 파일에 내용이 없는 시트를 **제외 목록이 아니라 데이터 목록에
0행으로** 표시한다.

### 왜

픽스처 #4의 `G_카테고리`가 그렇다 — 헤더 확신 0.95인데 데이터 0행이다. 이번 달에 광고
카테고리 실적이 없었을 뿐이고, 다음 달 파일엔 있을 수 있다.

요약으로 강등해 보이면 사용자가 "이 시트는 안 가져오는구나"로 학습하고, 다음 달에 데이터가
들어와도 확인하지 않는다.

### 규칙

- 역할은 구조로, 행 수는 내용으로 (ADR-002 §4)
- 0행 시트는 선택 가능한 상태로 두되 `0행`을 명시한다
