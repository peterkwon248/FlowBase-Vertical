# ADR-001 — Import 파이프라인 구현 스택

- **상태**: 채택
- **일자**: 2026-08-11
- **범위**: 헌장 B-9 (Import 파이프라인 6단계), D 세션 1·2

---

## 결정

**Import 파이프라인 6단계를 전부 TypeScript로 구현한다.** Tauri 백엔드(Rust)는 SQLite 접근과 파일시스템에 한정하고, 파싱 로직은 Rust로 내리지 않는다.

근거: 헌장 C-8이 지정한 upstream 이식 대상(formula parser/evaluator/cycles + 테스트, 파서, import-normalizers, SavedView 모델, 차트)이 전부 TypeScript다. 언어를 가르면 이식이 재구현이 되고, C-8이 명시한 "테스트 포함" 이식의 이점이 사라진다.

---

## 조건 (결정과 함께 확정)

### 1. 6단계 모듈 경계 엄수 — 단계별 Rust 포팅이 가능한 형태로

```
Recognition → Extraction → Normalization → Mapping → Validation → Load
```

각 단계는 **직렬화 가능한 입출력**으로만 이어진다. 단계 간에 클로저·클래스 인스턴스·라이브 스트림 핸들을 넘기지 않는다. 어느 한 단계가 실측 병목으로 판명되면 **그 단계만** Rust로 교체할 수 있어야 한다.

### 2. 파싱은 Worker에서, SheetJS는 CVE 없는 버전으로 고정

- 파싱은 Web Worker에서 수행한다. 메인 스레드 블로킹 금지.
- BIFF `.xls`도 SheetJS로 처리하고, **11번가 정산확정 픽스처로 검증**한다.
- 버전 고정 방법은 아래 "정정 사항" 참조.

### 3. SQLite 적재는 청크 단위 트랜잭션 배치 insert

행 단위 insert 금지. 청크마다 트랜잭션 하나로 묶는다.

### 4. 성능 합격 기준 — 세션 1에 추가

> **쿠팡 광고 픽스처(80,138행) 파싱 + 적재 30초 이내 (진행 표시 포함).**

실패 시 **Extraction 단계만** Rust 포팅을 세션 2에서 검토한다.

## 정정 사항 — 조건 2의 전제 확인 결과

조건 2는 "upstream `package.json`의 xlsx CVE 주석 참조"라고 지시했다. 실제 확인 결과 두 가지가 다르다.

**1. 주석 위치가 `package.json`이 아니다.**

`lib/xlsx-loader.ts` L9-11에 있다:

> `xlsx` (SheetJS community npm 버전)에 알려진 prototype pollution + ReDoS vulnerability 있음. 사용자가 자기 디바이스에서 자기 파일을 import하는 시나리오는 위험 낮음. 신뢰할 수 없는 xlsx를 직접 받는 시나리오 도입 시 (Phase 3+ 클라우드 sync) 재검토 필요.

관련 기록: `NEXT-ACTION.md:52`, `docs/SESSION-LOG.md:607,637` ("xlsx 2 high (No fix available)").

**2. upstream은 CVE 없는 버전으로 고정돼 있지 않다.** `package.json`은 `"xlsx": "^0.18.5"` — 취약한 버전 그대로다. upstream은 위험을 **수용**했지 해결하지 않았다.

**3. npm 레지스트리에는 CVE 없는 `xlsx`가 존재하지 않는다.** 확인 결과 npm `xlsx`의 `latest`는 지금도 **0.18.5**다. SheetJS는 npm 배포를 중단했고 이후 릴리스는 자체 CDN에만 있다 (git 태그 확인: 최신 **v0.20.3**).

| CVE | 내용 | 수정 버전 |
|---|---|---|
| CVE-2023-30533 | prototype pollution | 0.19.3 |
| CVE-2024-22363 | ReDoS | 0.20.2 |

**따라서 "CVE 없는 버전 고정"의 유일한 이행 방법은 CDN 타르볼 고정이다:**

```bash
npm install --save https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz
```

설치 시점에 CDN에서 최신 패치 버전을 재확인한다. 이 경로는 npm audit의 대상이 아니므로 버전을 문서에 명시해 추적한다.

### 조건 2-a. 타르볼 무결성 고정 (승인 2026-08-11)

**CDN 직접 의존은 공급망 리스크가 npm보다 한 단계 높다.** npm 레지스트리와 달리 불변성 보장이 없어, 같은 URL의 내용물이 조용히 바뀌어도 알 수 없다. 따라서 **해시가 바뀌면 빌드가 깨지게** 해둔다.

1. `package-lock.json`의 해당 항목 `integrity` 해시를 **커밋한다.** lock 파일을 gitignore하지 않는다.
2. **CI에서 검증한다.** `npm ci`는 lock의 `integrity`와 실제 내려받은 타르볼을 대조하고 불일치 시 실패한다 — CI 설치 명령은 `npm install`이 아니라 **반드시 `npm ci`**를 쓴다.
3. 해시를 의도적으로 갱신하는 경우(버전 업)는 **단독 커밋**으로 분리하고, 새 버전 번호와 갱신 사유를 커밋 메시지에 남긴다. 다른 변경에 섞어서 올리지 않는다.

이 조항의 목적은 편의가 아니라 **탐지**다. 무결성 불일치는 경고가 아니라 빌드 실패여야 한다.

## 알려진 위험 — 조건 4의 측정 범위

SheetJS `XLSX.read()`는 **전체 버퍼를 한 번에 읽어 워크북을 메모리에 올린다.** 입력 스트리밍 API가 없다 (`XLSX.stream`은 출력 전용). 80,138행 × 43열 = 약 344만 셀이 Worker 힙에 동시에 존재하게 된다.

이는 헌장 B-9의 "전체 메모리 적재 금지"와 정면으로 부딪힌다. 조건 4의 30초 기준은 **시간만 측정하므로, 속도로 통과하면서 B-9를 위반하는 상태를 못 잡는다.**

### 조건 4-a. 피크 메모리 상한 = 256MB (승인 2026-08-11)

> 쿠팡 광고 픽스처(80,138행) 처리 중 **Worker 피크 RSS 256MB 이하.**

기준은 셀러의 실기기다 — 8GB 노트북에서 브라우저·윙·엑셀을 동시에 띄운 채 돌아간다. Worker 하나가 512MB를 쓰면 실사용 체감이 나빠진다.

344만 셀이 dense 모드로 셀당 ~30바이트면 원본 문자열 포함 **200MB 안쪽이 현실적 목표**다.

**256MB는 벌칙이 아니라 판정선이다.** 못 맞추면 그것이 곧 "SheetJS 전량 적재의 한계"라는 판정이며, 조건 1의 단계별 Rust 교체 조항이 발동할 정당한 근거가 된다. 즉 초과는 실패가 아니라 **측정된 결론**이다.

완화책 (합격 기준과 무관하게 적용):
- `XLSX.read(buf, { dense: true })` — 희소 객체 대신 밀집 배열
- `cellStyles`·`cellHTML`·`cellFormula` 전부 off
- Extraction 출력을 청크로 잘라 Normalization에 흘려보내 워크북을 조기 해제

## 측정 결과 (2026-08-11, 세션 1)

`npm run perf` — 픽스처 #13 (80,138행 × 43열), Worker 스레드에서 실행.

| 항목 | 측정값 | 기준 | 판정 |
|---|---|---|---|
| 시간 | **10.6초** | 30초 | 통과 |
| 피크 RSS 증가분 | **+857MB** | 256MB | **초과 (3.3배)** |
| └ 그중 `XLSX.read` 직후 | **+569MB** | — | 우리 코드가 돌기 전 |

단계별: 읽기 6ms · 판정 0ms · **파싱 9,333ms** · 스트림 983ms.

**책임 소재가 갈렸다.** 워크북 적재만으로 569MB다 — 우리 스트리밍 코드가 시작하기도 전의 수치이고, 예산 256MB의 2.2배다. 셀당 약 165바이트이며, `dense: true`·`cellStyles`/`cellHTML`/`cellFormula`/`cellText`/`cellNF` 전부 끈 상태의 값이다. 남은 약 290MB는 스트리밍 중의 청크 버퍼와 GC 지연분으로, 전체의 3분의 1이다.

즉 이 초과는 튜닝으로 좁힐 수 있는 성질이 아니다. SheetJS는 셀마다 JS 객체를 하나씩 만들고, 344만 셀이면 그 자체가 예산을 넘는다. 옵션으로 줄일 여지는 이미 다 썼다.

**결론: 조건 1의 단계별 Rust 교체 조항이 발동한다.** 시간 기준은 여유 있게 통과했으므로 문제는 속도가 아니라 표현 방식이다. 필요한 것은 `sheet1.xml`을 SAX로 훑어 워크북을 실체화하지 않고 행을 흘려보내는 리더이며, 그 자리는 **Extraction 한 단계**다. 조건 1이 요구한 "직렬화 가능한 단계 경계"가 지켜져 있어 이 교체는 `RowChunk` 경계에서 끝난다 — 나머지 5단계는 손대지 않는다.

## 처방과 재판정 (2026-08-12)

판정 직후 승인된 처방은 **2단계**였다: 먼저 TypeScript로 SAX 경로를 만들어 보고(1일 박스),
그래도 256MB를 못 뚫으면 그때 같은 인터페이스로 Rust 포팅.

**1단계에서 해결됐다. Rust 포팅은 발동하지 않는다.**

`src/core/import/parsers/xlsx-sax.ts` — fflate 스트리밍 해제 + `sheet1.xml` 행 단위 스캔.
워크북을 만들지 않고 `RowChunk`로 흘려보낸다.

| | 이전 (SheetJS) | 이후 (fast path) | 기준 |
|---|---|---|---|
| 시간 | 10.6초 | **2.9초** | 30초 |
| 피크 RSS | +857MB | **+232MB** | 256MB |
| 행 수 | 80,138 | **80,138** | 80,138 |

세 기준 동시 충족. 파싱 단계만 보면 9,333ms → 187ms다.

### 설계를 정한 실측값 (#13 내부)

| | 값 | 함의 |
|---|---|---|
| `sheet1.xml` | 136MB (압축 10.5MB) | 문자열로 만들면 UTF-16이라 272MB — **통째로 디코드 금지** |
| `sharedStrings.xml` | 2.5MB · 62,050개 | 사전 1패스 로드가 저렴하다 (예상대로) |
| `styles.xml` | 674바이트 · 커스텀 numFmt 0개 · cellXfs 1개 | **날짜 서식이 없다.** 숫자는 전부 그냥 숫자 |

`<dimension>`은 `sheet1.xml` 선두를 조금만 풀고 멈춰서 읽는다 — `physicalRowCount`를
자리표시 0으로 내보내지 않기 위해서다.

### 게이트와 안전장치

fast path는 **5MB 초과 · 단일 시트 · 커스텀 숫자 서식 없음**을 전부 만족할 때만 탄다.
하나라도 못 채우면 사유와 함께 거절하고 SheetJS로 되돌아가며, 그 사유는
`ParsedSource.warnings`에 남는다.

**정확성 검증이 이 작업의 핵심이다.** 빠른데 다른 답을 내면 최악이다:

```
$ npx tsx tools/harness/verify-fast-path.ts 13
fast path  80,138행  6a297b70f4bf30f5  2223ms
SheetJS    80,138행  6a297b70f4bf30f5  11180ms
일치. 전 80,138행이 셀 값·타입까지 동일하다.
```

같은 대조가 테스트 스위트에도 들어 있다.

### 청크 크기도 실측으로 정했다

`DEFAULT_CHUNK_SIZE`를 5,000 → **1,000**으로 내렸다. 속도는 셋 다 같으므로 청크를 키워서
얻는 게 없다.

| 청크 | 피크 RSS | 판정 |
|---|---|---|
| 5,000 | +283MB | 초과 |
| 2,000 | +257MB | 초과 (1MB 차이) |
| **1,000** | **+231MB** | **통과** |
| 500 | +222MB | 통과 |

### 남은 선택지 (지금은 불필요)

1. Rust `quick-xml` SAX 리더 → `RowChunk`를 IPC로 — **보류.** 1단계로 충분했다
2. 멀티시트·날짜 서식 있는 대용량 파일이 나오면 fast path의 게이트를 넓힌다
3. 여유가 25MB(10%)로 얇다 — 더 큰 파일이 들어오면 재측정한다

1. ~~조건 4의 30초 기준 미달 → Extraction만 Rust 포팅~~ — **해소.** 1단계 SAX 경로로 통과
