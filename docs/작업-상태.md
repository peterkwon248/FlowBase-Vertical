### ★ 이 세션이 배운 것 — 다음 세션이 되풀이하지 말 것 ★

1. **소스 검사는 「그렸나」를 보지 「보이나」를 못 본다.** 768px 「더보기」는 배선을

## 인지된 부채

### ★ 파이프라인 6단계 중 **5단계만 실재한다** — Validation 미구현 (2026-08-15) ★

헌장이 선언한 단계는 여섯이다:

```
Recognition → Extraction → Normalization → Mapping → Validation → Load
                                                      ↑ 이 칸이 비어 있다
```

`validationRules`는 **모든 프로파일이 선언하는데 코드 어디에서도 읽지 않는다.**
타입 선언(`mapping/index.ts:207`)과 머리말 주석 말고는 참조가 0곳이다. 같은 계열이
둘 더 있다 — `extractionRules`의 `headerRowHint`·`sheetSelector`도 전 프로파일에
선언돼 있는데 파이프라인에 넘기는 호출부가 없다.

**이것은 조용한 실패(LOCK 6)가 아니라 «약속한 단계가 없는 것»이다.** 데이터가
틀리게 저장되는 게 아니라 검증이 애초에 안 돈다. 그래서 C 계열(조용한 실패)과
같은 대열에 넣지 않고 여기 적는다 — 섞으면 «고치는 일»의 크기가 뒤섞인다.

> **⚠ 2026-08-19 갱신 — 칸에 첫 입주자가 생겼지만 이 부채는 그대로다.**
> 계획 C가 `core/import/validation/identity.ts`(항등식 증명기)를 그 칸에 넣었다.
> 그러나 그것은 **판정 시 증명**(이 열이 무슨 필드인가)이고, 여기 적힌 부채는
> **적재 시 규칙 실행**(`validationRules`가 선언한 검사를 행마다 돌리는 것)이다.
> 둘은 이름만 같은 다른 일이다 — 증명기가 들어왔다고 이 절을 지우면 안 된다.
> `extractionRules`의 `headerRowHint`·`sheetSelector`도 여전히 호출부 0곳이다.

> **⚠ `signPolicy`는 이 부채가 아니라 잠재 결함이다 — 아래 «4번 대열» 참조.**
> ADR-009 ②(「저장은 양수, 의미는 타입이 정한다」)의 **집행자가 없다.** 선언만
> 있는 것과 규약을 어길 수 있는 것은 무게가 다르다.


### ★ `npm run convert:gate`는 **늘 빨갛다** — 판정은 테스트가 한다 (2026-08-14 확인) ★

`/after-work`로 전 게이트를 돌리다 나왔다. **내가 깨뜨린 것이 아니다** — `af9ad85`
(이번 세션 시작 전) 워크트리에서 돌려 보니 **같은 6개 항목이 이미 빨갛다.**

```
af9ad85     6개 항목 불일치 · 동적 자리 991건 차이
05d37b3     6개 항목 불일치 · 동적 자리 997건 차이   ← 이번에 선언한 이탈만큼 늘었다
9060480     6개 항목 불일치 · 동적 자리 원본 1272 / 출력 1265   (2026-08-19)
```

★ **항목 수(6)는 그대로이고 «동적 자리» 차이만 는다 — 그게 정상이다** ★ CLI는
자리를 **순서대로** 대조하므로, 신설 구간 안에 홀을 하나 더하면 그 뒤가 통째로
한 칸씩 밀려 «불일치»로 세어진다. 2026-08-19에 imp* 홀 4개(`impSheetAutoNote` ·
`impAllSheets` · `impAllSheetsLabel` · `toggleImpAllSheets`)를 더해 차이가 커졌다.
판정하는 쪽(`tests/convert-gate.test.ts`)은 그대로 **12개 전부 통과**하고, 그 안의
«`data-s21` 표식 총수 = `S21_REGIONS.length`» 단언이 «선언 없는 새 구간이 없다»를
지킨다. **숫자가 늘어난 것을 회귀로 읽지 마라 — 항목 6개가 7개가 되면 그때가 회귀다.**

원인은 구조다. CLI(`tools/convert/gate.ts`)는 목업과 출력을 **그대로** 비교하고
**선언된 이탈을 모른다.** `DEVIATIONS`와 `S21_REGIONS`는 `tests/convert-gate.test.ts`
안에 있고, 그 테스트가 이탈을 반영해 대조한 뒤 **12개 전부 통과**한다.

> **§21 패치가 처음 올라간 날부터 CLI는 빨갰다.** gate.ts의 머리말이 그 사실을 이미
> 예고하고 있다 — *"§21 이탈은 별도 커밋에서 의도적으로 만들고, 그 커밋의 diff가 곧
> 목업과 다른 곳의 전체 목록이 된다."*

**왜 그냥 두면 안 되나**: 늘 빨간 게이트는 **사람을 훈련시켜 게이트를 무시하게
만든다.** 새 세션이 «전 게이트 확인»을 하다 이걸 만나면 없는 사고를 좇거나,
반대로 «원래 빨간 거»라며 진짜 회귀까지 넘기게 된다.

**처방(미착수)**: 이탈 선언(`DEVIATIONS`·`S21_REGIONS`)을 테스트에서 **모듈로 빼서
CLI와 공유**한다. 그러면 CLI가 테스트와 같은 답을 내고 둘 다 녹색이 된다.
지금 안 하는 이유는 이 세션의 범위 밖이고, 잘못 옮기면 **게이트의 보증 범위가
조용히 넓어지는** 변경이라 그 자체로 검토가 필요해서다.

**그동안의 규율**: 보존 게이트의 판정은 `npm test`가 한다. `convert:gate` CLI는
«선언되지 않은 이탈이 몇 건인지» 세는 참고 도구로만 읽는다.

### ★ 위저드 v1은 파이프라인을 **메인 스레드**에서 돌린다 — ADR-001 조건 2 위반 ★

조건 2는 «파싱은 Worker에서»다. 위저드 v1은 그러지 않는다. **조용한 위반과 기록된
부채는 다르므로** 여기 적는다.

```
실전 기준으로 순서를 정했다 — 8월 정산 파일은 수백 행이라 문제가 없다
그러나 쿠팡 광고(8만 행 · ~10MB)는 스모크 실측으로 9.5~10.4초 화면이 멈춘다
```

그동안의 방어는 **고지 하나**다 (`data-s21="import-big"` · 4MB 이상):

> *"큰 파일입니다. 가져오는 동안 화면이 잠시 멈출 수 있습니다 — 앱이 멈춘 것이
> 아니라 파일을 읽고 있는 중입니다. 창을 닫지 말고 기다려 주세요."*

**고지 없는 10초 프리즈는 강제 종료를 부른다.** 사용자의 자연스러운 반응이
"죽었나?"이기 때문이다. 미리 말하면 같은 10초가 "크니까 그렇구나"가 된다.
고칠 수 없는 것을 숨기지 않는 것이 지금 할 수 있는 정직이다.

**해소 조건**: Worker 이관. 그때 `import-big` 구간과 `BIG_FILE_BYTES` 상수를
함께 지운다 — 임시물의 수명을 §21-7과 같은 방식으로 묶어 둔다.

개정 전은 `233 · 244.8 · 249 · 267.3`으로 4회 중 1회 초과였다.

**벽이 옮겨갔다.** 단계별 재측정:

```
파싱만                  ~205MB      ← 새 벽. 예산의 80%
+ 정규화 + 매핑         ~207-218MB  (평탄화 이전 245MB → 사실상 0)
+ SQLite 적재           ~246MB
                        ────────
예산                     256MB
```

정규화는 이제 공짜다. ADR-003이 "JS 파이프라인 232MB"라 묶어 부른 것의 대부분은
**파싱이었다.** 다음에 메모리를 더 줄여야 하면 손댈 곳은 파서다 — 정규화가 아니다.

**정직하게**: 여유 1.7MB에 관측 폭 59.3MB(195.2~254.3)다. 다음 회차가 넘을 가능성을
배제할 수 없다. 세션 3에서 실파일이 늘면 다시 볼 자리다.

> **갱신 (2026-08-15)** — C 계열 이후 4회는 `219.2 · 244.2 · 254.3 · 251.9`다. 최대가
> 249.7에서 **254.3으로 올라가 관측 폭이 195.2~254.3이 됐다.** 회귀로 보지 않는
> 근거는 «옛 폭 안»이 **아니라**(254.3은 250 밖이다) «예산 안 + 구조적 무접촉»이다.
> 3회로 추세를 만들지 않는다 — 다만 **넘는 회차가 나오면 그때 팔 곳은 파서**다.

재현: `npm run e2e` · `SKIP_LOAD=1 npm run e2e`(적재 제외) · `npm run perf`(파싱만)

### 3. ~~Tauri 창이 화면에 뜨지 않는다~~ → **오진이었다. 실측으로 기각** (2026-08-13)

1단 스크린샷을 찍다가 "앱은 도는데 창이 안 보인다"를 만났고, 처음엔 제품 결함으로
적었다. **틀렸다.** 실측이 두 가지를 갈라줬다.

**① `-16000 @ 157x25`의 정체 — 그냥 최소화된 창이다.**

```
+0s   2586x1656 @ (294,129)      vis=T  iconic=False   창 생성
+2s   2586x1656 @ (147,29)       vis=T  iconic=False   fit 적용 · 포커스
+4s   314x50    @ (-32000,-32000) iconic=True          ← 최소화
```

`-32000 @ 314x50`은 Windows가 **최소화된 창을 주차하는 표준 자리**다. 내 열거
스크립트가 DPI 비인식이라 200% 배율에서 절반으로 보여 `-16000 @ 157x25`가 됐다 —
**두 값은 같은 것이었다.** 도구가 만든 착시를 새 현상으로 읽은 것이다.

**② 최소화의 범인은 실행 방식이었다.**

```
에이전트 셸에서 Start-Process   →  +4s에 최소화된다
explorer.exe로 실행 (정상 실행)  →  90초 내내 정상. 상태 변화 0
```

우리 코드에 `minimize` 호출은 프론트·Rust 통틀어 **0건**이다(grep). 즉 앱이
아니라 **비대화형 셸에서 띄운 프로세스의 포커스 처리**가 만든 현상이었다.

> **교훈은 도구 쪽이다.** 앞으로 앱을 눈으로 확인할 때는 `explorer.exe <exe>`로
> 띄운다. `Start-Process`로 띄우고 "창이 안 뜬다"고 판정하면 없는 버그를 좇게 된다.
> 그리고 **측정 도구의 좌표계를 먼저 의심한다** — DPI 비인식 스크립트가 200%
> 기기에서 내놓는 숫자는 절반이다.

### ★ 그 뒤 더 정확해졌다 — 검증층의 경계선 (2026-08-13) ★

정산 화면을 스크립트로 눌러 보려다 재현 조건이 좁혀졌다:

| `.tmp/pnl-backup-*.sqlite` | 마이그레이션 전에 뜬 백업 · gitignore | 없어도 무관. 이 기기에는 `pnl-backup-2026-08-19-premigrate.sqlite`(마이그레이션 8 시점)가 있다 |
| Vercel 배포 상태 | 저장소 밖 | `main`에 푸시하면 자동 재배포된다. **배포별 고정 주소(`…-htk49re5a-…`)는 그 시점 빌드에 영구 고정**이라 새로고침해도 안 바뀐다 — 늘 `flow-base-vertical.vercel.app`으로 연다 |

원본 픽스처가 필요하면 사용자의 `플로우베이스용 엑셀 자료.zip`을 `fixtures/raw/`에 푼다.
