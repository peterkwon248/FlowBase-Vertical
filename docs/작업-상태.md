## 막혀 있는 것 두 개

### 1. 합격 기준 2 — 메모리가 기준선에 걸쳐 있다

```
시간    5.1초 / 30초                          통과
행 수   80,137 = 80,137 = 80,137              일치
메모리  233 · 244.8 · 249 · 267.3MB / 256MB   4회 중 1회 초과
```

중앙값은 안쪽이지만 **통과로 선언하지 않았다.** 4번 중 1번 깨지는 측정을 최선의 회차로
합격시키면 안 된다.

재현: `npm run e2e`

**어디에 무게가 있는지 실측했다** (ADR-003):

```
파싱 + 정규화              ~232MB
+ 매핑                     ~245MB   (+13MB)
+ SQLite 적재              ~263MB   (+18MB)
                            ────────
예산                        256MB
```

**적재를 0으로 만들어도 245MB로 예산의 96%다.** 드라이버 교체로는 안 풀린다 —
실제 레버는 **JS 파이프라인의 232MB**다.

편차도 적재가 만든다. 적재를 빼면 ±3.5MB → **±0.5MB**로 떨어진다.

**다음 카드**: `NormalizedValue`가 셀마다 `{kind, value, raw}` 객체 3필드다.
80,137행 × 43컬럼이면 **340만 개**가 생성된다(동시 생존은 청크 하나뿐이지만 RSS는
할당 총량을 따라간다). 평평한 배열로 바꾸는 것이 첫 후보.

재현: `npm run e2e` · `SKIP_LOAD=1 npm run e2e`(적재 제외) · `npm run perf`(파싱만)

### 2. ~~ADR-003 — Rust 미설치~~ → 해소

Rust 1.97.1 stable-msvc + MSVC Build Tools 설치 완료. 링크 확인됨.
[ADR-003](ADR-003-sqlite-바인딩.md) 확정 — **rusqlite를 Tauri 커맨드 뒤에.**

`tauri-plugin-sql`을 버린 이유는 성능이 아니라 **커맨드 표면**이다. 플러그인은
프론트엔드가 임의 SQL을 실행하게 해서, 합격 기준 4("전체 테이블 적재 경로 없음")를

적재 처리량은 rusqlite가 약 3배(1,700~1,950ms → 545~692ms). 벤치는 `bench/sqlite/`
(저장소 안 — 다른 기기에서도 `cargo run --release`로 재현된다. Rust 툴체인 필요).

## 기기를 오가며 작업한다

이 저장소는 데스크톱 3대 · 노트북 · 핸드폰에서 번갈아 열린다. 그래서
**세션의 시작과 끝을 저장소 안 명령으로 고정**해뒀다.

| | |
|---|---|
| `/before-work` | 원격을 당겨오고 · 의존성을 맞추고 · 정상인지 확인하고 · 어디서부터인지 보고 |
| `/after-work` | 검증하고 · 커밋하고 · 푸시하고 · (필요하면) PR 만들고 · 이 문서를 갱신하고 · **닫혔는지 확인** |

둘 다 `.claude/commands/`에 있다 — **저장소 안이라 clone하면 어느 기기에서든 뜬다.**
`~/.claude/commands/`에 두면 그 기기에서만 되므로 여기 둔 것이다.

**기기를 바꿀 때는 `/after-work`로 닫고 옮긴다.** 닫지 않고 옮기면 다음 기기에서
`/before-work`가 "원격이 뒤처져 있다"거나 갈라진 상태를 보고하게 되고, 그때는
합치는 방법을 물어본다 — 자동으로 rebase하지 않는다.

## 새 기기에서 이어받기

```bash
git clone https://github.com/peterkwon248/FlowBase-Vertical.git
cd FlowBase-Vertical
npm ci          # package-lock의 integrity 해시로 SheetJS 타르볼까지 검증된다
npm test        # 115개 통과해야 정상
```

Node 22.5+ 필요 — `node:sqlite`(저장 계층)와 `TextDecoder('euc-kr')`(인코딩 감지)를 쓴다.

`bench/sqlite`를 돌리려면 Rust 툴체인이 추가로 필요하다 (없어도 `npm test`·`npm run e2e`는
전부 동작한다). 이 기기는 설치돼 있고, 새 기기에서는:

```bash
winget install --id Rustlang.Rustup                      # Windows
winget install --id Microsoft.VisualStudio.2022.BuildTools --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

Build Tools는 UAC 승인이 필요하다 — `Start-Process -Verb RunAs`로 띄우면 클릭 한 번으로 된다.

### 그대로 되는 것

`npm test` · `npm run harness` · `npm run perf` · `npm run e2e` 전부 동작한다.
테스트와 하네스는 기본으로 `fixtures/clean/`(커밋됨)을 보기 때문이다.

### 따라오지 않는 것

| | 왜 | 없으면 |
|---|---|---|
| `fixtures/raw/` (15.6MB) | 실명·연락처·주소 포함, gitignore (헌장 E-10) | `tools/deident/*` 실행 불가. `#8 원본` 테스트는 자동 skip되므로 `npm test`는 정상 통과 |
| `_ref/` (11.7MB) | 스크린샷·대행사 리포트, 앱 코드 아님 | 참고 자료만 없음. 코드·문서에 영향 없음 |
| Claude 메모리 | `~/.claude/projects/.../memory/`는 기기 로컬 | 작업 방식 메모 2건. 내용은 ADR 규율로 저장소에 반영돼 있다 |
| 태스크 목록 | 세션 로컬 | 이 문서가 대체한다 |

원본 픽스처가 필요하면 사용자의 `플로우베이스용 엑셀 자료.zip`을 `fixtures/raw/`에 푼다.
비식별화본을 다시 만들려면 그다음 `npx tsx tools/deident/apply.ts` → `verify.ts`.

## 이 프로젝트의 작업 리듬

세션 1·2에서 반복해 효과를 본 것들이다. 계속 이렇게 간다.

1. **지시서의 전제도 실측으로 확인한다.** 세 번 틀렸다 — xlsx CVE 주석 위치,
   대조표의 ragged/헤더행/TOTAL 3건, B-2가 전제한 자연 키의 존재.
   정정은 환영받는다
2. **가설은 세우고 실측으로 기각한다.** "파생 시트는 수식으로 만들어진다"는 그럴듯했지만
   실측에서 깨졌다 (ADR-002 §4)
3. **가드는 부러뜨려 확인한다.** 안 잡는 가드는 없느니만 못하다 (G-1)
4. **결정은 ADR로.** 조건·정정·측정 결과·재검토 트리거까지 한 문서에
5. **교차 검증은 양방향이다.** 사용자의 헌장 대비 diff가 U-1을, 우리 테스트가 대조표
   오류 3건을 잡았다
