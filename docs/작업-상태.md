### 1. ~~합격 기준 2 — 메모리~~ → 통과. 다만 여유가 얇다

`NormalizedValue` 평탄화를 실행했다 ([ADR-007](ADR-007-정규화-표현.md)).
셀당 `{kind, value, raw}` 객체 344만 개 → **청크당 평면 배열 3개**.

```
12회 연속 — 195.2 · 211.2 · 217.4 · 228.9 · 230 · 235.3
            237 · 238.2 · 242.6 · 243 · 248.5 · 249.7
중앙값 236.2 · 최대 249.7 / 256MB     12회 전부 통과
시간   4.9~5.0초 / 30초
행 수  80,137 = 80,137 = 80,137
```

개정 전은 `233 · 244.8 · 249 · 267.3`으로 4회 중 1회 초과였다.

**벽이 옮겨갔다.** 단계별 재측정:

```
파싱만                  ~205MB      ← 새 벽. 예산의 80%
+ 정규화 + 매핑         ~207-218MB  (평탄화 이전 245MB → 사실상 0)
+ SQLite 적재           ~246MB
                        ────────
예산                     256MB
```

정규화는 이제 공짜다. ADR-003이 "JS 파이프라인 232MB"라 묶어 부른 것의 대부분은
**파싱이었다.** 다음에 메모리를 더 줄여야 하면 손댈 곳은 파서다 — 정규화가 아니다.

**정직하게**: 여유 6.3MB(2.5%)에 관측 폭 54MB다. 13번째 회차가 넘을 가능성을
배제할 수 없다. 세션 3에서 실파일이 늘면 다시 볼 자리다.

재현: `npm run e2e` · `SKIP_LOAD=1 npm run e2e`(적재 제외) · `npm run perf`(파싱만)

### ★ 단일 계산기 원칙 (LOCK) ★

**여기서 만드는 손익 3층 계산기가 유일한 구현이다.**

이후 UI 이식에서 화면은 이 계산기를 **소비만** 한다. 목업의 `profit()`을 두 번째
진실로 이식하는 것은 **금지**다 — 계산이 두 벌이 되는 순간 화면과 CLI가 다른 답을
내고, 그 차이는 아무도 모르게 쌓인다 (헌장 A-5).

따라서 must-fix 중 **계산 계열(이슈 20 고정비 안분 · 22 기간 스코프 · 23 NEW_SEED
제외)은 이식 시점의 수정이 아니라 이 계산기가 처음부터 옳게 구현하는 것으로
해소된다.** 3a-d에는 계산이 아닌 것(이슈 3 테마·19 대사·21·41 하드코딩)만 남는다.

### ★ 이식의 기준이 바뀌었다 — §21 ★

```
프론트 기준 = 동결 목업 + §21
충돌 시 §21이 목업을 이긴다
```

[§21 — 표면·근거·재배치 체계](§21-표면-근거-재배치.md)가 헌장 C의 부속으로 채택됐다
(2026-08-12). 적용 시점은 **3a-b 이식**이며 별도 디자인 라운드를 두지 않는다.

**목업을 충실히 재현하면 오히려 위반이 되는 자리가 있다.** 실측으로 확인한 것:

| §21 | 목업 | 이식 시 |
|---|---|---|
| 도넛 → 가로 막대 | `Donut` 4곳·`Pie` 존재 | 교체 |
| 스파크라인 제거 | `spark` 18곳 존재 | KPI 카드에서 삭제 |
| 좌측 모서리 층 표식 폐기 | **목업에 없음** | 새로 그리지만 않으면 됨 |
| 워터폴 | **목업에 없음** | 신규 요소 — 헌장 E-1과 충돌, 미결 |

§9·§15-3 원문을 받아 §21 본문에 반영했다 — **§9에서 대체되는 것은 M 규칙
하나뿐**이고 존치 조항(기능 제거 ❌·2탭 도달·hover 금지·요소 생략 ❌ 등)은 그대로
구속력이 있다.

**§21 쪽 미결은 0건이다** (2026-08-12 전부 해소):
- 표식 겹침 → **확정: 겹친다.** 밑줄은 층("판단인가"), 점은 origin("원본을 덮었나").
  다른 질문에 답하므로 각자 붙는다
- 워터폴 vs E-1 → **신설 승인.** E-1은 에이전트의 자체 판단 발명을 막는 조항이고
  §21은 사람이 승인한 개정이라 대상이 아니다. 예외는 §21 목록 안에서만 열린다

## 다음 손이 갈 곳 — DC 템플릿 변환기 (승인됨)

**손으로 옮기지 않는다.** `FlowBase.dc.html`은 443KB이고 `renderVals()`가 1,900줄이라,
손 이식은 "조용히 어긋나도 아무도 모르는" 경로다. 기계로 옮기고 **보존 게이트**가
어긋남을 잡는다 — `equivalence` 하네스와 같은 발상이다 (ADR-007).

핸드오프 §4-1이 변환표를 이미 완성해서 줬다:

```
{{ path }}        →  {expr}          <sc-if value>  →  {cond && …}
<sc-for list as>  →  .map()          $index         →  .map((x, i) =>)
<x-import>        →  import          <x-dc>·hint-*  →  삭제
```

### 파이프라인은 3단으로 고정한다 (조건 2)

```
① 변환 (기계, 100% 충실)  →  ② 보존 게이트 통과  →  ③ §21 패치 (손, 커밋 분리)
```

**§21 이탈을 변환 도중에 끼워 넣지 않는다.** 도넛→가로막대·스파크라인 제거를
변환기가 하면 게이트가 "의도된 이탈"과 "사고"를 구분하지 못한다.
§21 패치는 **별도 커밋**이고, 그 커밋의 diff가 곧 *"목업과 의도적으로 다른 곳의
전체 목록"*이 된다 — 나중에 "이거 왜 목업이랑 달라?"의 답이 git log에 산다.

### 보존 게이트가 비교하는 것 (조건 1)

정적 구조 수준에서 본다. **JSX를 렌더한 DOM이 아니다** — `{{ path }}` → `{expr}`는
값이 아니라 **자리**의 치환이기 때문이다.

| 대상 | 왜 |
|---|---|
| 텍스트 노드 | 카피가 바뀌면 안 된다 |
| 클래스 | Vector DS 클래스가 살아 있어야 한다 |
| 토큰 | `var(--…)` 참조 보존 |
| **인라인 `style` 속성값** | ★ 이 목업은 **토큰이 인라인 style에 박힌 코드**다 (드롭존 L313~331이 그렇다). 클래스만 비교하면 style 드리프트가 샌다 |
| **동적 자리의 개수·경로** | 1:1 대응을 봐야 표현식 누락까지 잡힌다 |

요약: **구조와 정적 속성의 완전 보존 + 동적 자리의 1:1 대응.**

### 손 이식한 드롭존은 첫 시험이다 (조건 3)

`src/app/App.tsx`의 온보딩은 내가 **손으로** 옮긴 것이다. 변환기가 나오면 그 출력과
대조한다. 다르면 —

> **변환기가 기준이 아니라 목업이 기준이다.**
> 둘 다 목업 원문(L313~331 · L5696~5704)과 대조해서 어긋난 쪽을 고친다.
> 손 이식이 맞고 변환기가 틀렸을 수도 있다. **시험의 정답은 항상 원본이다.**

### `renderVals` 1,900줄 분해 — 변환기 스코프 **밖**이다 (조건 4)

여기가 이식 전체에서 "조용히 어긋나기" 제일 좋은 자리다 — 계산 로직을 옮기다
살짝 다르게 쓰는 것. 방어선은 이미 있다: **`computePnl`이 유일한 계산기**다
(단일 계산기 LOCK).

```
분해 규칙
  데이터 접근  →  리포지토리로
  계산        →  computePnl **호출로 대체**한다 (옮기지 않는다)
  남는 것     →  표시용 포맷팅뿐
```

**renderVals 안의 산수가 JSX 쪽으로 한 줄이라도 복사되면 두 번째 진실이 생긴다.**

| "시스템 폰트 폴백으로 뜬다" | 시스템이 아니라 **CDN에서 받아 쓰고 있었다** — `document.fonts`에 `Pretendard Variable / loaded` |

즉 결함은 "폰트가 없다"가 아니라 **"인터넷이 있어야 브랜드 폰트가 뜬다"**였다.
로컬퍼스트 앱에서 더 나쁜 쪽이고, 개발 기기가 온라인이면 **화면이 멀쩡해 보여서
아무도 눈치채지 못한다.** 이 항목이 계속 뒤로 밀린 이유이기도 하다.

`fonts/`에 파일을 넣는 대신 **npm으로 번들**했다 — `pretendard@1.3.9` (OFL-1.1,
CDN과 같은 버전). package-lock의 integrity로 검증되고 `npm ci`로 재현된다.
저장소에 2MB 바이너리를 영구히 얹지 않아도 된다. 검증: 외부 `@import` 0건 ·
`document.fonts`에 여전히 loaded · `dist/`에 `PretendardVariable.woff2` 2,057KB 포함.

> **같은 종류의 문제가 셋이었다** — `mockup/ds/icons.jsx`의 Lucide CDN,
> 그리고 이 폰트 CDN. 둘 다 번들로 옮겼다(같은 자산, 전달 방식만 변경 —
> 발명이 아니다). **"로컬퍼스트인데 네트워크를 타는 곳"을 찾을 때는 CDN
> 문자열을 grep하는 것이 가장 빠르다.**

미구현 저장 6종은 [다음-마이그레이션-대기목록](다음-마이그레이션-대기목록.md)에,
세션 3이 만들 UI 요구 5건은 [§18-개정사항](§18-개정사항.md)에 있다.

## 기기를 오가며 작업한다

이 저장소는 데스크톱 3대 · 노트북 · 핸드폰에서 번갈아 열린다. 그래서
**세션의 시작과 끝을 저장소 안 명령으로 고정**해뒀다.

| | |
|---|---|
| `/before-work` | 원격을 당겨오고 · 의존성을 맞추고 · 정상인지 확인하고 · 어디서부터인지 보고 |
| `/after-work` | 검증하고 · 커밋하고 · 푸시하고 · (필요하면) PR 만들고 · 이 문서를 갱신하고 · **닫혔는지 확인** |

둘 다 `.claude/commands/`에 있다 — **저장소 안이라 clone하면 어느 기기에서든 뜬다.**
`~/.claude/commands/`에 두면 그 기기에서만 되므로 여기 둔 것이다.

**기기를 바꿀 때는 `/after-work`로 닫고 옮긴다.** 닫지 않고 옮기면 다음 기기에서
`/before-work`가 "원격이 뒤처져 있다"거나 갈라진 상태를 보고하게 되고, 그때는
합치는 방법을 물어본다 — 자동으로 rebase하지 않는다.

```bash

Node 22.5+ 필요 — `node:sqlite`(저장 계층)와 `TextDecoder('euc-kr')`(인코딩 감지)를 쓴다.

`bench/sqlite`를 돌리려면 Rust 툴체인이 추가로 필요하다 (없어도 `npm test`·`npm run e2e`는
전부 동작한다). 이 기기는 설치돼 있고, 새 기기에서는:

```bash
winget install --id Rustlang.Rustup                      # Windows
winget install --id Microsoft.VisualStudio.2022.BuildTools --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

Build Tools는 UAC 승인이 필요하다 — `Start-Process -Verb RunAs`로 띄우면 클릭 한 번으로 된다.

### 그대로 되는 것

`npm test` · `npm run harness` · `npm run perf` · `npm run e2e` · `npm run dev` ·
`npm run build` 전부 동작한다. 테스트와 하네스는 기본으로 `fixtures/clean/`(커밋됨)을
보기 때문이다.

**단 `npx tsx tools/harness/pnl.ts`는 원본이 필요하다** — 기본이 `fixtures/raw/`다
(실파일 관통이 목적이라 비식별화본으로는 의미가 없다). 원본이 없으면 `--clean`으로
구조만 확인할 수 있다.

### 따라오지 않는 것

| | 왜 | 없으면 |
|---|---|---|
| `fixtures/raw/` (15.6MB) | 실명·연락처·주소 포함, gitignore (헌장 E-10) | `tools/deident/*` 실행 불가. `#8 원본` 테스트는 자동 skip되므로 `npm test`는 정상 통과 |
| `_ref/` (11.7MB) | 스크린샷·대행사 리포트, 앱 코드 아님 | 참고 자료만 없음. 코드·문서에 영향 없음 |
| Claude 메모리 | `~/.claude/projects/.../memory/`는 기기 로컬 | 작업 방식 메모 2건. 내용은 ADR 규율로 저장소에 반영돼 있다 |
| 태스크 목록 | 세션 로컬 | 이 문서가 대체한다 |
| `dist/` · `.tmp/` | 빌드·측정 산출물, gitignore | `npm run build`·`npm run e2e`가 다시 만든다 |
| `gh` 인증 | 기기 로컬 | 푸시는 Git Credential Manager가 따로 처리한다. `gh`는 PR 상태 표시용이며 없어도 작업에 지장 없다 — 필요하면 `gh auth login` |

원본 픽스처가 필요하면 사용자의 `플로우베이스용 엑셀 자료.zip`을 `fixtures/raw/`에 푼다.
비식별화본을 다시 만들려면 그다음 `npx tsx tools/deident/apply.ts` → `verify.ts`.

## 이 프로젝트의 작업 리듬

세션 1·2에서 반복해 효과를 본 것들이다. 계속 이렇게 간다.

1. **지시서의 전제도 실측으로 확인한다.** 세 번 틀렸다 — xlsx CVE 주석 위치,
   대조표의 ragged/헤더행/TOTAL 3건, B-2가 전제한 자연 키의 존재.
   정정은 환영받는다
2. **가설은 세우고 실측으로 기각한다.** "파생 시트는 수식으로 만들어진다"는 그럴듯했지만
   실측에서 깨졌다 (ADR-002 §4)
3. **가드는 부러뜨려 확인한다.** 안 잡는 가드는 없느니만 못하다 (G-1).
   **그리고 "안 깨졌다"도 해석해야 한다** — 가드가 무른 것일 수도, 그 코드 경로가
   애초에 안 쓰이는 것일 수도 있다. 둘은 전혀 다른 결론이다 (ADR-007)
4. **결정은 ADR로.** 조건·정정·측정 결과·재검토 트리거까지 한 문서에
5. **추정으로 넘어간 자리는 나중에 그대로 버그가 된다.** 실제 사례:
   97,600원 차이를 처음엔 "7월 밖 3행"이라고 **추정하고 넘어갔다.** 그때 실측했으면
   거기서 잡혔을 것이 며칠 뒤 "모든 기간 조회가 매달 말일을 잃는다"는 구조적 결함으로
   드러났다. 이 원칙은 지시서의 전제(1번)뿐 아니라 **자기 작업 이력에도** 적용된다
6. **교차 검증은 양방향이다.** 사용자의 헌장 대비 diff가 U-1을, 우리 테스트가 대조표
   오류 3건을 잡았다
