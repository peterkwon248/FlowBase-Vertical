# §20 보강 — 확인 질문

채택 2026-08-14. **설계만. 구현은 트리거 후.**

> ⚠ 이 문서는 «아직 짓지 않은 것»의 설계다. 워터폴(§21)이 검증층 부재를 이유로
> 3단으로 밀린 것과 **같은 논리**다 — 실측할 대상이 없으면 짓지 않는다.

## 원칙

결정론 5층이 확정하지 못한 컬럼은 **조용히 고르지 않고 소리 내어 묻는다.**

```
별칭 → 값 신호 → 문서 맥락 → 항등식 → 개인 프로파일
```

다섯을 다 통과하고도 남는 것만 질문이 된다.

## 규칙 5

1. **질문 최소화.** 5층을 전부 통과한 뒤 남는 것만 묻는다. **3개를 넘으면 설계
   실패**로 간주하고, 질문을 다듬기 전에 원인(프로파일 부족)을 먼저 본다.
2. **후보에 근거 필수.** %가 아니라 **검증 문장**이다 —
   *"판매합계−공제와 128행 일치"*. §21-1 계보이고, 결함 52에서 «일치도 %»를
   «선언»으로 바꾼 것과 같은 이유다.
3. **«이 열은 쓰지 않음»이 항상 선택지다.** 강제로 고르게 하지 않는다.
4. **답 = 프로파일 갱신** (기억하기 체크 시). 다음 파일부터 질문 0.
5. **답 = 사용자 판단으로 기록** (`entered_by`, L2에서 추적 가능).

## 레이아웃

확인 단계의 **매핑 표는 유지한다** (사용자 확정 — 전체를 조망하는 값이 있다).
그 **위에** «확인이 필요한 항목 N» 카드 섹션을 얹는다.

동작 셋:

| | |
|---|---|
| 카드 ↔ 표 행 | 양방향 연결 |
| 질문 0개 | **섹션 자체가 없다** (빈 섹션을 그리지 않는다 — §21-7 계보) |
| 미응답 | **진행 가능.** 해당 열은 «쓰지 않음» 처리하고 **다이제스트에 명시**한다 |

미응답을 막지 않는 이유는 §22의 금지 조항과 같다 — **안내지 검문이 아니다.**

## 구현 트리거

**8월 실전 이후, 애매 컬럼이 실측으로 1회 이상 발생했을 때.**

그 전까지는 이 문서만 있는다. 오늘 지으면 물어볼 것이 없어 빈 섹션만 렌더되고,
그것을 확인하려고 가짜 애매 컬럼을 만드는 순간 3a 게이트(시드 잔재 0건)를
검증을 위해 어기는 순환에 빠진다.

## 지금 쌓인 관련 실측

리허설(2026-08-14)에서 **확인 단계가 컬럼의 역할을 과소 보고**하는 결함이 나왔다.
`fieldMappings`만 읽고 `sourceKey`·`listing`·`rowRouting`을 안 봐서, 행 식별 키와
리스팅 제목의 출처가 «이 프로파일이 쓰지 않는 컬럼»으로 표시된다
([목업-결함-발견분](목업-결함-발견분.md) 53).

**이 결함은 트리거를 기다리지 않는다.** 확인 질문은 «모르는 것을 묻는» 기능이고,
저것은 «아는 것을 틀리게 말하는» 결함이라 계열이 다르다.
