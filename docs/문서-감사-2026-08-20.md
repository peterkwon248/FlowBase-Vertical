## E. ★ 감사가 틀린 것 — 반증 2건 ★

감사도 틀린다. 릴레이 전에 실측해서 걸렀다.

### E-1. 「묶음이 매출만 좁히고 원가·운영비는 안 좁힌다」 — **거짓**

ADR 갈래가 **높음**으로 올렸다. 직접 쟀다:

```
전체     매출 30,000 · 매입원가 5,000 · 운영비 2,500 · 고정비 3,100,000
「A만」   매출 10,000 · 매입원가 2,000 · 운영비 1,000 · 고정비 3,100,000
```

**원가·운영비는 정확히 좁아진다** — `ITEM_JOIN`이 `active_order_item`을 지나기 때문이다.
감사가 「원가 **표**가 안 걸린다」를 보고 「**합**이 안 걸린다」로 넘겨짚었다.

안 좁는 건 **고정비 하나**고 그건 설계상 맞다(임대료는 어느 파일을 보든 같다).
→ **결함 아님. ADR-021에 「묶음이 좁히는 것 / 안 좁히는 것」 한 줄만 적는다.**

### E-2. 「부록 B 18줄이 전부 참」 — 1줄은 이미 거짓

`ensureConnection`은 `App.tsx:1128`이 부른다. **목록이 갱신 안 되니 신뢰도까지 떨어진다.**
실체는 살아 있으므로 줄을 **다시 써야** 한다 — 「연결 ID가 마켓당 하나로 뭉친다」.

1. **쓰기 실패 전수** — `writeThenReload(...).then`의 `r.error` 분기가 `take` 또는

2. **잠금 침묵 전수** — `!acquire()` 뒤 3줄 안에 이유를 말하는지. **오늘 10곳이 붉어진다**
3. **무동작 버튼 전수** — `onClick={vals.X}`의 `X`가 빈 함수인 채 재할당 0이면 실패.
   **오늘 6개가 붉어진다**
4. **「센 것은 말한다」** — `data.ts`에서 `console.warn`으로만 끝나는 실패 분기 0
5. **사용자 쓰기는 반드시 어딘가에 남는다** — A-4-4를 잡고, 앞으로 생길 「batch 없는
   쓰기 경로」도 잡는다
6. **매니페스트 골든 대조** (B-1)
7. **localStorage 금지어** — 지금 0이므로 **깨끗할 때 못박는다**
8. **Fact 화면 드래그 금지** — 지금 0. 칸반을 붙이는 날 자동으로 걸린다

### F-2. 「사용자 불변식」 문서 신설 — ✅ `docs/사용자-불변식.md`

LOCK 10개를 세면 **거의 전부 엔지니어링을 향해 있다.** 사용자를 향한 건 6·8 둘뿐이다.
「넣은 파일은 전부 장부에 보인다」 같은 **사용자 쪽 불변식이 애초에 목록에 없었다** —
A-4-4는 그 빈자리에서 나왔다.

10문장 이내로 짓고, **가능한 것부터 F-1로 승격한다.** LOCK 10이 안 뚫리는 이유가 그거다.

### F-3. ADR 템플릿에 「파급면」 절 — ✅ `docs/ADR-템플릿.md`

*"이 결정이 닿는 표면 전수 — 특히 LOCK 6 재적용"*.
위 세 표본이 전부 그 자리에서 잡혔을 것이다.

### F-4. 부록 B에 마감 루프 — ✅ 18줄 전부 판정

18줄 각각에 **만든다(언제) / 선언을 지운다** 중 하나를 붙인다.
**「집행 없는 선언을 유지하는 제3의 선택지」를 없앤다.** 그게 오늘 사고의 재발 방지다.

즉시 지워도 되는 5줄(약속하는 화면 0): `applyAdjustments`+`castToColumn` ·
`adjustmentsFor` · `credential_ref`/`state_note` · 「비용 룰」

## B-2 후일담 — 깨우니 바로 하나가 붉어졌다

`dashboard-wiring.test.ts`의 「비용 구성」 단언이 **즉시 실패**했다. 그리고 그건
회귀가 아니라 **잠든 시험이 낡은 것**이었다 — 날짜가 증명한다:

```
그 단언          2026-08-15   ← 그 뒤로 한 번도 안 돌았다
costMix 층 정리   2026-08-17   ← 「미배분은 기여이익 아래 칸」 + 라벨 「직접 광고비」
```

단언은 `adDirect + adUnallocated > 0 → 라벨 「광고비」`였는데 **두 군데가 틀렸다**:
라벨이 바뀌었고, 미배분을 더하면 **층을 섞는다**(합이 매출을 넘어 도넛이 거짓말한다).

고치면서 **조였다** — 08-17에 미배분을 뺐는데 *그걸 지키는 시험이 없었다.* 누가 다시
더해도 아무 데서도 안 걸렸다. 그 단언을 새로 넣었고, 자해로 확인했다(둘 다 붉어진다).

> ⚠ **이 시험의 초록을 「광고비 배선 확인됨」으로 읽으면 안 된다.**
> `snapshot.ts:524`의 `adDirect: 0` 리터럴(A-1 · 0순위) 때문에 `else` 가지만 돈다.
> 그 결함이 고쳐지는 날 `if` 가지가 자동으로 켜진다. 리터럴 자리에 그 사실을 적어 뒀다.

## G. 순서 제안

```
0  A-1 (숫자가 틀린다)          ← 앱이 지금 거짓말한다
1  A-2·A-3 (죽은 버튼 · 좁은 화면) ← 「고장」으로 읽힌다
2  A-4 (조용한 실패)  + F-1 1~5   ← 고치면서 동시에 기계로 못박는다
3  C (틀린 문장) + 날짜 정본       ← 반나절. 다음 세션의 전제를 바로잡는다
4  B-2·B-7 (CI 스텝 둘)  ✅ 완료 — 깨우자마자 낡은 단언 1건이 붉어졌다 (아래)
5  D (작업-상태 분할) + F-2·F-3   ← 구조
6  B-1·B-3 (매니페스트 · 메모리 판정)
```

**0~2가 「근거 층」보다 먼저다.** 근거를 보여주는 층을 짓기 전에,
지금 보여주는 숫자가 맞아야 한다.
