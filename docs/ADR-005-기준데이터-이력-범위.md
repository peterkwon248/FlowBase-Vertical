# ADR-005 — v1 기준 데이터의 변경 이력 범위

- **상태**: 채택 · **2026-08-19 개정** (재검토 트리거 발동 — 맨 아래 「개정」 절)
- **일자**: 2026-08-12
- **범위**: 헌장 B-4 (데이터 3종 분류 — 기준 데이터의 "수동 편집 + 변경 이력")
- **발견**: 헌장 B부 대비 diff 검수 (U-2). 조용한 축소를 막기 위한 명시적 결정 요구

---

## 결정

**v1의 변경 이력은 «손익 계산에 들어가는 기준 데이터»만 시계열로 갖는다.
나머지 기준 데이터는 `updated_at`만 둔다.**

> 원문은 「원가만」이었다. 2026-08-19에 고정비·운영비가 같은 조건을 통과해
> 들어왔고(맨 아래 개정), 기준이 «원가»라는 **품목**에서 «과거를 다시 계산하는
> 데 쓰이느냐»라는 **성질**로 또렷해졌다. 범위가 넓어진 것이지 규칙이 바뀐 것이
> 아니다 — 원문의 판단 기준은 처음부터 이 성질이었다.

| 기준 데이터 | v1 | 근거 |
|---|---|---|
| 원가 (`cost_history`) | **시계열 이력** | 아래 |
| 고정비·운영비 (`overhead`) | **시계열 이력** | 2026-08-19 개정. 아래 |
| 상품 (`product`) | `updated_at` | |
| SKU (`sku`) | `updated_at` | |
| 상품 연결 (`marketplace_listing`) | `updated_at` + `linked_at`·`linked_by` | |
| 매핑 프로파일 (`mapping_profile`) | **버전이 곧 이력** (B-6) | 기존 버전 수정 금지, 변경은 새 행 |

---

## 왜 원가만인가 — 이력의 성격이 다르다

원가의 이력은 **과거를 다시 계산하기 위해** 필요하다. 인계 문서 §5:

> 원가는 숫자 하나가 아니라 시계열이다. `SKU.cost = 12000`이 아니라 적용 시작일이 붙은
> 이력이다. `costAt(skuId, 주문일)`이 그 주문일 이전 중 가장 늦은 단가를 쓴다.

7월 주문의 손익은 **7월에 유효했던 원가**로 계산해야 한다. 오늘 원가를 올렸다고 지난달
이익이 바뀌면 그건 틀린 숫자다. 즉 원가 이력은 감사 기록이 아니라 **계산의 입력**이다.

나머지는 다르다. 상품명이 바뀌었을 때 지난달 리포트를 옛 이름으로 다시 그릴 이유가 없고,
연결을 바꿨을 때 과거 집계를 옛 연결로 되돌릴 이유도 없다. 이들의 과거 값은 **감사
목적**이고, v1에는 그 요구가 없다.

## 이 결정이 축소인 것은 맞다

헌장 B-4는 기준 데이터 전반에 "변경 이력"을 적었다. 이 결정은 그 범위를 좁힌다.
**조용히 좁히지 않기 위해** 여기 적는다.

되돌릴 수 있는 형태로 좁혔다는 점이 근거다:
- `cost_history`가 **패턴을 이미 확립**했다 (대상 + 종류 + 금액 + 적용 시작일 + 입력자)
- 다른 기준 데이터에 이력이 필요해지면 같은 모양의 테이블을 추가하면 된다.
  기존 테이블의 컬럼을 바꾸지 않으므로 소급 문제가 없다
- 헌장 B-1의 "소급 추가 불가"는 **Fact 행의 공통 컬럼**에 대한 규정이고, 기준 데이터의
  이력 테이블은 거기 해당하지 않는다

## 재검토 트리거

1. 상품·SKU 이름 변경이 과거 리포트에 영향을 준다는 요구 발생 → 해당 이력 테이블 추가
2. 감사 요구(누가 언제 무엇을 바꿨나)가 생김 → 기준 데이터 전반에 변경 로그 도입 검토
3. 연결 재매핑으로 과거 집계가 흔들리는 사례 발생 → `marketplace_listing` 이력화

# 개정 — 2026-08-19: 고정비·운영비를 이력에 넣는다

## 무엇이 바뀌나

`overhead` 표(마이그레이션 010)가 `cost_history`와 **같은 모양**을 갖는다:
대상(`label`) + 종류(`kind`) + 금액 + 적용 시작일 + 입력자.

## 왜 — 원 결정의 기준을 그대로 통과한다

이 ADR이 「원가만」이라고 좁힌 근거는 **«과거를 다시 계산하기 위해 필요한 이력만
시계열로 둔다»**였다. 감사 목적의 이력은 v1에서 뺐다. 고정비는 전자다:

```
3월에 임대료가 180만 → 220만으로 올랐다
→ 2월 손익은 **180만으로 계산돼야 한다.**  오늘 값으로 지난달이 바뀌면 틀린 숫자다
```

원가와 **같은 성질의 문제**이고, 원 결정문이 그 경우를 이미 예고해 뒀다:

> 다른 기준 데이터에 이력이 필요해지면 같은 모양의 테이블을 추가하면 된다.
> 기존 테이블의 컬럼을 바꾸지 않으므로 소급 문제가 없다

이게 그 첫 사례다. **재검토 트리거 1의 변형**(과거 리포트에 영향을 주는 요구)이고,
기존 테이블을 건드리지 않았으므로 원 결정의 「되돌릴 수 있는 형태」 조건도 지켜졌다.

## 지우기가 없다는 것이 이 모양의 핵심이다

사무실을 뺐으면 「임대료 삭제」가 아니라 **금액 0원을 6월 1일부터**다. 행을 지우면
5월 손익에서도 임대료가 사라진다 — 과거가 바뀐다. 「0원」과 「없음」이 다르다는
것은 원가에서 이미 세운 규율이고(증정품·샘플의 0원), 여기서도 같다.

## 함께 온 것 — `overhead_stance`는 **이력이 아니다**

「고정비를 두지 않는다」는 선언은 상태이지 시계열이 아니다. 지난달의 선언으로
지난달을 다시 계산할 일이 없다 — **계산에 안 들어가고 문장만 고른다.** 그래서
PK가 `(library_id, kind)` 하나이고 덮어쓴다. 이 ADR의 「나머지는 `updated_at`만」
쪽에 속한다.

경계를 이렇게 긋는 이유: **금액은 계산의 입력이고 선언은 화면의 입력**이다.
둘을 같은 모양으로 만들면 «2월에는 두지 않기로 했었다»를 저장하게 되는데, 그
정보로 할 수 있는 일이 없다.

## 여전히 안 하는 것

상품·SKU·연결의 이력은 그대로 없다. 이 개정은 **손익 계산에 들어가는 기준
데이터**로 범위를 넓힌 것이지 기준 데이터 전반으로 넓힌 것이 아니다.
재검토 트리거 2·3은 그대로 살아 있다.
