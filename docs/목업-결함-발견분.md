# 목업 결함 발견분 · 사본 수정 대장

> **이 문서가 없으면 "목업이랑 다른데?"가 사고인지 수정인지 아무도 모른다.**

프론트 기준은 **동결 목업 + §21**이고, 충돌 시 §21이 목업을 이긴다
([§21](§21-표면-근거-재배치.md)). 그래서 우리 코드가 목업과 달라지는 자리는
세 종류뿐이며, 각각 다른 곳에 기록된다:

| 이탈 종류 | 어디에 남나 |
|---|---|
| **의도적 디자인 이탈** (도넛→가로막대 등) | §21 패치 커밋의 diff |
| **목업 결함 수정** (동작하지 않는 것을 고침) | ★ 이 문서 §1 |
| **사본 수정** (DS/테마 CSS를 우리가 고침) | ★ 이 문서 §2 |
| 기계 변환 오차 | 있으면 안 된다 — 보존 게이트가 잡는다 |

> ★ **마크업 이탈은 이제 기계도 센다** (2026-08-13) ★
> `tests/convert-gate.test.ts`의 **`DEVIATIONS`**가 목업과 일부러 다른 마크업 자리의
> 기계 검사판이다. 원래 게이트 규칙은 "diff 0"이었는데, 목업을 그대로 따르면 오히려
> 헌장을 어기는 자리가 실재해서(아래 46) 선택지가 "게이트를 빨간 채로 두기"뿐이었다.
> **빨간 게이트는 곧 꺼진다.** 그래서 이탈을 선언하게 만들었고, 게이트는 오히려 강해졌다 —
> 선언 밖의 차이는 여전히 실패하고, **선언이 낡아도**(목업에 그 문구가 더는 없어도) 실패한다.
> 사람이 읽는 판은 이 문서, 기계가 세는 판은 그 배열이다. **둘 다 있어야 한다.**

[핸드오프 §5](핸드오프.md)가 목업의 알려진 문제 **43건**을 이미 적어뒀다.
여기 있는 것은 **그 목록 밖에서 뒤늦게 발견한 것**이라 44번부터 이어 붙인다.

### 48. "다음 가져오기부터 자동으로 붙습니다" — 미구현 동작을 약속한다

**상태: 수정 완료 (2c) · `DEVIATIONS` 2건이 지킨다**

> ★ **자리가 하나가 아니었다** ★ 판정할 때는 `done` 탭 꼬리말만 봤는데, 2c에서
> 마크업을 열자 **상단 안내문에도 같은 약속**이 있었다 (목업 L2436):
>
> ```
> done 탭  L2493   "…  다음 가져오기부터 자동으로 붙습니다"
> 안내문   L2436   "… 다음 **동기화**부터 자동으로 붙습니다"   ← 위반이 둘이다
> ```
>
> 안내문 쪽은 **LOCK 10("동기화" 금지)까지 겹친다** — 결함 46과 같은 계열이 같은
> 화면에 또 있었던 것이다. 판정은 한 문장을 보고 내렸지만 **수정은 문구를 전부
> 찾아서** 해야 한다는 사례로 남긴다.

| | |
|---|---|
| **증상** | 상품 연결 화면이 두 자리에서 *"자동으로 붙습니다"*라고 적는다. **절반만 참이다** |
| **원인** | ADR-012가 보증하는 것은 *같은 `listing_key`가 다시 오면 연결이 유지된다*뿐이다. **새 리스팅의 자동 연결은 정의한 적이 없다** — 새 옵션(`색상:그린`)이 오면 `unlinked`로 태어난다 |
| **근거 조항** | §17-3(용어·정직 표기) — 결함 46("동기화" 카피)과 **정확히 같은 계열**이다. 둘 다 목업이 아직 없는 동작을 카피로 약속한 자리 |
| **수정** | 두 자리 모두. `done` 탭 → `"같은 리스팅이 다시 오면 이 연결이 유지됩니다"` · 안내문 → `"한 번 이어주면 같은 리스팅이 다시 올 때 그 연결이 유지됩니다"`. ADR-012가 실제로 보증하는 것의 정확한 문장이다 |
| **왜 자동 연결을 만들지 않나** | 새 옵션이 기존 SKU와 같은 SKU인지는 **사실이 아니라 판단**이다(옵션마다 원가가 다를 수 있어 SKU를 가르는 게 맞을 수도 있다). 작업 리듬 12 — **검토 전에 접는 층은 결정론적이어야 한다.** todo 탭에 뜨는 것이 정직한 동작이다 |
| **정직함의 가격** | **클릭 한 번.** 새 옵션이 todo에 뜨면 기존 SKU가 `clear` 후보로 바로 잡힌다 — `tests/linking-view.test.ts`의 "새 옵션은 unlinked로 태어난다"가 그 동작을 지킨다 |
| **기계 검사** | `tests/convert-gate.test.ts`의 `DEVIATIONS` 2건 (안내문 · done 꼬리말) |
| **테스트** | `tests/linking-screen.test.ts` — "done 탭 카피가 ADR-012가 보증하는 것만 말한다" (`"자동으로 붙습니다"`·`"동기화"` 둘 다 부재를 단언) |

### 50. 세 번째 "동기화" — 조건 뒤에 숨어 있었다

**상태: 수정 완료 · LOCK 10을 기계 검사로 승격시킨 계기**

| | |
|---|---|
| **증상** | 상품 화면 원가 안내문: *"…여기서 직접 입력하고, **동기화**가 덮어쓰지 않습니다."* (목업 → `Template.tsx` L3053) |
| **원인** | 결함 46·48과 같은 뿌리 — 목업은 마켓 API로 동기화되는 세계를 전제하고 그렸다 |
| **근거 조항** | **LOCK 10.** 어휘는 연결 / 가져오기 / batch |
| **수정** | `"가져오기가 덮어쓰지 않습니다"`. 문장의 뜻은 원래 참이었고 **어휘만 우리 것으로** 바꿨다 — 원가는 기준 데이터고 가져오기는 사실만 넣으므로 사실관계도 그대로다 |
| **★ 왜 세 번이나 놓쳤나** | 이 자리는 `ctCogs` 조건 뒤에 있고 `emptyVals()`가 `ctCogs: false`를 준다. **어떤 렌더 검사로도 이 문장은 나오지 않는다** — 전 화면 렌더 게이트가 녹색인 채로 위반이 남아 있었을 것이다 |
| **그래서 바뀐 것** | 금지어 검사를 **두 층**으로 세웠다. 소스 전수(조건 뒤 정적 카피) + 렌더(vals가 런타임에 만든 문구). 어느 한쪽도 다른 쪽을 대신하지 못한다 |
| **기계 검사** | `DEVIATIONS` 1건 · `tests/screen-safety.test.ts`의 «§17-3 금지어» 3건(소스·렌더·가드 부러뜨리기) |

> **카피 결함의 수정 단위는 «발견 지점»이 아니라 «문구 전수»다.**
> 결함 48에서 배운 것이 여기서 값을 했다 — 판정은 한 문장을 보고 내렸지만 실제로는
> done 탭·안내문 두 자리였고, 전수로 훑자 상품 화면에 **세 번째**가 나왔다.
> 사람이 매번 훑는 대신 기계가 훑도록 옮긴 것이 위 검사다.

### 51. 수량·구성 표기가 토큰화에서 증발한다 — «1+1»과 단품이 100% 동점

**상태: 판정 대기.** 목업 결함이 아니라 **우리 매처의 결함**이지만, 발견 경로가 2d
실사용이라 여기 함께 둔다 (연결 화면에서 사용자가 마주친다).

| | |
|---|---|
| **증상** | `1+1 한일의료기 3D 에어매쉬 쿨패드 정품 공급처`(1+1 묶음)와 `한일의료기 3D 에어매쉬 쿨패드 정품 공급처`(단품)가 **일치도 100%로 동점**이다 |

| **실측** | 두 제목 모두 `[한일의료기, 3d, 에어매쉬, 쿨패드]`로 정규화된다 |
| **고칠 때 따라오는 것** | 임계값(0.74 · margin 0.15 · shared 2)이 **실측 분포에서 나온 값**이라(ADR 계열) 토큰 규칙을 바꾸면 `tools/harness/listing-match-dist.ts`로 분포를 다시 떠서 절단점을 재확인해야 한다 |
| **당장의 대처** | 그 카드는 `contested`로 뜨므로 **미리 골라지지 않는다.** 사람이 고르는 구조가 이 결함의 피해를 막고 있다 — 작업 리듬 12가 설계대로 작동한 자리다 |

## §2. 사본 수정 — 원본과 다른 곳

`src/app/styles/`는 목업 `_ds/`와 `ds/`의 **사본**이다. 우리가 통제하는 파일이지만
원본과의 diff가 추적되지 않으면 **DS 업데이트를 받을 때 수정이 조용히 증발한다.**
그래서 고친 자리를 여기 남긴다.

### 2-1. `vector-tokens.css` — 폰트를 CDN에서 번들로

| | |
|---|---|
| **원본** | `@import url("https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/…")` |
| **수정** | `@import url("pretendard/dist/web/variable/pretendardvariable.css")` (npm) |
| **이유** | 로컬퍼스트 앱이 인터넷 없이는 브랜드 폰트를 잃는다. `ds/icons.jsx`의 Lucide CDN과 같은 문제이고 같은 방식으로 고쳤다 |
| **주의** | 이 결함은 **개발 기기가 온라인이면 보이지 않는다.** 실제로 `document.fonts`에 `Pretendard Variable / loaded`가 있어 "시스템 폰트 폴백"으로 오인돼 있었다 |
| **커밋** | `5fda19b` |

### 2-2. `flowbase-theme.css` — `.nav-scrim`에 `display: block` 추가

| | |
|---|---|
| **원본** | `.nav-scrim { position: fixed; inset: 0; z-index: 210; background: … }` (display 없음) |
| **수정** | 같은 규칙에 `display: block` 한 줄 추가 |
| **이유** | §1-45의 DS 순서 버그를 덮는다. **`vector-app.css`는 건드리지 않았다** — DS 사본은 upstream과 대조 가능해야 하므로, 나중에 로드되는 우리 테마에서 덮는 쪽을 골랐다 |
| **커밋** | `f50712f` |

### 손대지 않은 사본

`vector-app.css` · `vector-base.css` · `vector-sidebar.css` · `vector-numeric.css`는
원본 그대로다. §1-45의 버그가 그 안에 있지만 **덮어서 해결**했다.

### 63. 필드매핑 배너가 «미확인» 한 마디뿐이다 — 초안의 상태를 말할 자리가 없다

| | |
|---|---|
| **증상** | 목업의 필드매핑 경고 배너는 «이 양식은 아직 확인되지 않았습니다…» 고정 문구 하나다. B2에서 드롭다운을 고르면 **저장 전 초안**이 생기는데, 그 개수·뜻·저장할 수 없는 이유(최소 한 벌 부족)를 말할 자리가 없다 |
| **원인** | 목업 시절에는 저장 경로가 없었다 — 배너가 말할 «상태»가 하나뿐이었다 |
| **근거 조항** | LOCK 6 — 확인 버튼을 조용히 죽이면 사용자는 왜 안 되는지 모른다. 이유는 버튼 옆에서 말한다 |
| **수정** | 배너 문장을 동적 자리(`fmWarnText`)로 바꿨다. 미확인 양식이면 동결 문구를 글자 그대로, 초안이 있으면 «고친 매핑 N건…» 또는 «저장할 수 없습니다 — 이유»를 그린다 |
| **커밋** | 이 커밋 (convert-gate `DEVIATIONS`에 짝 선언) |

### 64. 필드매핑 드롭다운이 전부 살아 있다 — 구조 열을 골라도 갈 곳이 없다

| | |
|---|---|
| **증상** | 목업은 모든 열의 드롭다운이 살아 있다. 그런데 행 식별 키·라우팅·리스팅 열의 매핑은 값 하나가 아니라 **적재의 구조**를 바꾸므로 v1 편집 범위 밖이다 (`deriveProfile`이 거부한다) |
| **원인** | 목업 시절에는 고른 것이 어디로도 가지 않았다 — 살아 있어도 탈이 없었다 |
| **근거 조항** | ADR-006 (행 식별 키를 바꾸면 기존 batch와 새 batch가 서로를 못 알아본다) · LOCK 6 (살아 있는 척하며 고른 것을 버리는 쪽이 더 나쁘다) |
| **수정** | 구조 역할 열의 `<select>`에 `disabled`를 준다. 잠긴 이유는 근거 열이 이미 말하고 있다 (« 행 식별 키를 구성한다…»). 미확인 양식(파생의 발판이 없는 것)도 전열 잠금 |
| **커밋** | 이 커밋 (convert-gate `DEVIATIONS`에 짝 선언) |

### 62. 시트 목록이 행 수를 두 번 말한다 — «1000행 · 1,000행»

| | |
|---|---|
| **증상** | 시트 선택 목록의 부가 설명이 `1000행 · 1,000행 · 수식 100%`로 나온다 |
| **원인** | `SheetInfo.reason`이 이 워크북에서 문자 그대로 `"1000행"`인데, 화면이 거기에 `won(physicalRowCount) + "행"`을 **한 번 더** 붙인다. 같은 사실을 두 번 쓰는 것을 아무도 안 봤다 |
| **근거 조항** | §21 — 근거는 «왜 그렇게 봤는가»를 말해야 한다. 같은 수를 두 번 쓰면 근거가 아니라 잡음이고, 자릿수 구분이 없는 쪽이 먼저 나와 **읽는 사람이 다른 수인 줄 안다** |
| **수정** | `reason`이 행 수와 같은 문자열이면 뺀다 — 자릿수 구분이 있는 쪽만 남긴다 |
| **발견 경위** | 전 시트 탐색을 붙이며 시트 목록을 실제 파일로 렌더해 보다가 나왔다. 그전에는 시트 목록을 **눈으로 볼 일이 없었다** |
| **커밋** | 이 커밋 |

## 등재 규칙

1. 목업과 다르게 만들었으면 **여기 아니면 §21 패치 커밋** 둘 중 하나에 반드시 남는다
2. 결함 번호는 핸드오프 43건에 이어 붙인다 (44, 45, …)
3. 각 항목에 **증상 · 원인 · 근거 조항 · 수정 · 커밋**을 적는다.
   근거 조항이 없으면 그건 결함 수정이 아니라 **임의 변경**이므로 §21 개정을 먼저 받는다
4. 사본 수정은 파일별로 원본 값과 바뀐 값을 나란히 적는다 — DS 업데이트 때 이 표가 병합 목록이 된다
