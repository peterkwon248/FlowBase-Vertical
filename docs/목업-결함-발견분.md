# 목업 결함 발견분 · 사본 수정 대장

> **이 문서가 없으면 "목업이랑 다른데?"가 사고인지 수정인지 아무도 모른다.**

프론트 기준은 **동결 목업 + §21**이고, 충돌 시 §21이 목업을 이긴다
([§21](§21-표면-근거-재배치.md)). 그래서 우리 코드가 목업과 달라지는 자리는
세 종류뿐이며, 각각 다른 곳에 기록된다:

| 이탈 종류 | 어디에 남나 |
|---|---|
| **의도적 디자인 이탈** (도넛→가로막대 등) | §21 패치 커밋의 diff |
| **목업 결함 수정** (동작하지 않는 것을 고침) | ★ 이 문서 §1 |
| **사본 수정** (DS/테마 CSS를 우리가 고침) | ★ 이 문서 §2 |
| 기계 변환 오차 | 있으면 안 된다 — 보존 게이트가 잡는다 |

> ★ **마크업 이탈은 이제 기계도 센다** (2026-08-13) ★
> `tests/convert-gate.test.ts`의 **`DEVIATIONS`**가 목업과 일부러 다른 마크업 자리의
> 기계 검사판이다. 원래 게이트 규칙은 "diff 0"이었는데, 목업을 그대로 따르면 오히려
> 헌장을 어기는 자리가 실재해서(아래 46) 선택지가 "게이트를 빨간 채로 두기"뿐이었다.
> **빨간 게이트는 곧 꺼진다.** 그래서 이탈을 선언하게 만들었고, 게이트는 오히려 강해졌다 —
> 선언 밖의 차이는 여전히 실패하고, **선언이 낡아도**(목업에 그 문구가 더는 없어도) 실패한다.
> 사람이 읽는 판은 이 문서, 기계가 세는 판은 그 배열이다. **둘 다 있어야 한다.**

[핸드오프 §5](핸드오프.md)가 목업의 알려진 문제 **43건**을 이미 적어뒀다.
여기 있는 것은 **그 목록 밖에서 뒤늦게 발견한 것**이라 44번부터 이어 붙인다.

## §1. 목업 결함 — 핸드오프 43건 밖

### 44. 하단 탭바의 "더보기"가 사이드바를 열지 못한다

| | |
|---|---|
| **증상** | 좁은 화면(S)에서 탭바 "더보기"를 눌러도 아무 일이 없다. 사이드바가 열리지 않으므로 탭바에 없는 **나머지 11개 화면으로 갈 길이 사라진다** |
| **원인** | 목업 L5686~5688의 `pick`이 `setState({ navOpen: true })`를 하는데, 렌더는 `navOpen = !this.state.navCollapsed`(L3909)를 읽는다. 서로 다른 상태다 — `navOpen`은 세팅만 되고 아무도 읽지 않는다 |
| **근거 조항** | §21의 §9 존치 조항 — **"어떤 브레이크포인트에서도 기능 제거 ❌ — 접는다. 모든 기능 최대 2탭 도달"**. 11개 화면이 도달 불가이므로 정면 위반 |
| **수정** | `openNav`를 별도 액션으로 두고 `navCollapsed: false`로 연결 ([shell.ts](../src/app/shell.ts)의 `TABBAR`) |
| **커밋** | `f50712f` |
| **테스트** | `tests/shell.test.ts` — "★ 더보기가 사이드바를 연다 ★" |

### 45. `.nav-scrim`이 CSS 순서 때문에 영영 보이지 않는다

| | |
|---|---|
| **증상** | 좁은 화면에서 서랍이 열려도 뒤가 덮이지 않는다. 그리고 **서랍을 닫을 수 없다** — 햄버거 버튼이 서랍(z-index 220) 아래로 가리므로 스크림이 유일한 탈출구인데 그게 안 보인다 |
| **원인** | `vector-app.css`가 L36(미디어 안)에서 `.nav-scrim { display: block }`을 주고 **L91(미디어 밖)에서 다시 `display: none`**을 준다. 미디어 쿼리는 특이성을 올리지 않으므로 파일 뒤쪽의 `none`이 항상 이긴다 |
| **성격** | 목업 고유가 아니라 **Vector DS 원본**의 결함이다. 목업은 그 파일을 그대로 링크할 뿐이다 |
| **근거 조항** | 이탈이 아니라 **버그 수정**이다 — 마크업(`nav-scrim`)과 핸들러(`closeNav` L5355)가 목업에 멀쩡히 있고, CSS가 그 의도를 죽이고 있었다. §21 "2탭 도달"에도 걸린다 |
| **수정** | DS 사본을 건드리지 않고 나중에 로드되는 `flowbase-theme.css`에서 `display: block`을 되살렸다 → §2-2 |
| **커밋** | `f50712f` |

### 46. "데이터 신선도" 카드가 존재하지 않는 동기화를 말한다

| | |
|---|---|
| **증상** | 카드 하단에 *"마켓 API 장애와 무관하게 마지막 성공 **동기화** 데이터로 계속 조회됩니다"*라고 적혀 있다. 우리는 마켓 API를 부르지 않는다 — 파일 가져오기뿐이다. **일어나지 않는 일을 설명하는 문장**이다 |
| **원인** | 목업은 연결이 API로 동기화되는 세계를 전제하고 그렸다 (`CONNS`의 `state`·`last`가 전부 시드다) |
| **근거 조항** | **LOCK 10 — "동기화" 카피 금지** (양방향·자동이 실존하기 전까지). 문서 우선순위상 헌장이 목업을 이긴다. 덧붙여 LOCK 6(조용한 실패 금지)에도 걸린다 — 읽지 못한 것을 표시해야 하는데 이 카드는 **다 잘 되고 있다고** 말한다 |
| **수정** | 카드를 **"이 숫자가 담지 못한 것"**으로 돌린다. 행은 `core/profit/gaps.ts`의 `pnlGaps` 결과이고, 이는 CLI가 손익 밑에 늘 출력하던 단서와 **같은 판정**이다. 하단 문장도 사실로 교체 |
| **왜 이 카드인가** | §21-4의 "소비 지점 표식"이 이 역할의 정위치다. 새 마크업을 발명하면 헌장 E-1에 걸리므로 **구조는 그대로 두고 내용만** 바꿨다 |
| **되돌아올 자리** | 진짜 연결 신선도(연결별 마지막 가져오기 시각)는 연결 배선이 생길 때 **자기 카드를 받는다.** 이 카드를 뺏은 것이 아니라 빈 슬롯을 먼저 쓴 것이다 |
| **기계 검사** | `tests/convert-gate.test.ts`의 `DEVIATIONS` 2건 (제목 · 하단 문장) |
| **테스트** | `tests/dashboard-wiring.test.ts` — "단서가 화면에도 있다" · `"동기화"는 화면에 없다` |

### 47. 헤더 부제가 시드의 달을 사실인 척한다

| | |
|---|---|
| **증상** | 7월 데이터를 띄웠는데 헤더에 **"손익 대시보드 2026년 8월"**. 바로 아래 히어로는 "2026년 7월 순이익"이라 **한 화면에 두 달이 동시에** 있었다 |
| **원인** | 목업 L3667의 `TITLES.dash`가 `["손익 대시보드", "2026년 8월"]` 상수다. 목업 시드가 8월이라 그때는 맞았고, 이식하면서 **상수째로 따라왔다** |
| **근거 조항** | LOCK 6(조용한 실패 금지)의 정면이다. **빈 값이면 사용자가 모르고 넘어가지만, 틀린 값은 믿는다** — 빈 화면보다 나쁘다 |
| **수정** | `dashboardVals`가 `vals.subtitle = periodLabel(period)`로 **기간에서 파생**시킨다. 상수는 데이터 없을 때의 기본값으로만 남는다 |
| **어떻게 걸렸나** | ★ **진짜 Tauri 창을 띄워 눈으로 보고서야** ★ — 전 게이트 녹색이었다. 작업 리듬 7번 세 번째 사례 |
| **테스트** | `tests/dashboard-wiring.test.ts` — "헤더 부제가 보고 있는 기간과 같다" |

> **같은 종류가 3건 더 남아 있다** — `vs 7월 같은 기간`(L1242) · `숫자 = 8월 누계 …
> 막대는 8/1 → 8/8`(L1406) · `전월 대비` ×6(L1459). 전부 `Template.tsx`의 **정적
> 텍스트**라 `DEVIATIONS` 선언이 필요하고 §21 패치(2단)에서 처리한다.
> 처리 방향은 **문장을 고치는 것이 아니라 문장의 존재 조건을 데이터에 묶는 것**이다 —
> 비교 데이터가 없으면 렌더되지 않고, 8월 데이터가 들어오는 날 **스스로 살아난다.**

## §2. 사본 수정 — 원본과 다른 곳

`src/app/styles/`는 목업 `_ds/`와 `ds/`의 **사본**이다. 우리가 통제하는 파일이지만
원본과의 diff가 추적되지 않으면 **DS 업데이트를 받을 때 수정이 조용히 증발한다.**
그래서 고친 자리를 여기 남긴다.

### 2-1. `vector-tokens.css` — 폰트를 CDN에서 번들로

| | |
|---|---|
| **원본** | `@import url("https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/…")` |
| **수정** | `@import url("pretendard/dist/web/variable/pretendardvariable.css")` (npm) |
| **이유** | 로컬퍼스트 앱이 인터넷 없이는 브랜드 폰트를 잃는다. `ds/icons.jsx`의 Lucide CDN과 같은 문제이고 같은 방식으로 고쳤다 |
| **주의** | 이 결함은 **개발 기기가 온라인이면 보이지 않는다.** 실제로 `document.fonts`에 `Pretendard Variable / loaded`가 있어 "시스템 폰트 폴백"으로 오인돼 있었다 |
| **커밋** | `5fda19b` |

### 2-2. `flowbase-theme.css` — `.nav-scrim`에 `display: block` 추가

| | |
|---|---|
| **원본** | `.nav-scrim { position: fixed; inset: 0; z-index: 210; background: … }` (display 없음) |
| **수정** | 같은 규칙에 `display: block` 한 줄 추가 |
| **이유** | §1-45의 DS 순서 버그를 덮는다. **`vector-app.css`는 건드리지 않았다** — DS 사본은 upstream과 대조 가능해야 하므로, 나중에 로드되는 우리 테마에서 덮는 쪽을 골랐다 |
| **커밋** | `f50712f` |

### 손대지 않은 사본

`vector-app.css` · `vector-base.css` · `vector-sidebar.css` · `vector-numeric.css`는
원본 그대로다. §1-45의 버그가 그 안에 있지만 **덮어서 해결**했다.

## 등재 규칙

1. 목업과 다르게 만들었으면 **여기 아니면 §21 패치 커밋** 둘 중 하나에 반드시 남는다
2. 결함 번호는 핸드오프 43건에 이어 붙인다 (44, 45, …)
3. 각 항목에 **증상 · 원인 · 근거 조항 · 수정 · 커밋**을 적는다.
   근거 조항이 없으면 그건 결함 수정이 아니라 **임의 변경**이므로 §21 개정을 먼저 받는다
4. 사본 수정은 파일별로 원본 값과 바뀐 값을 나란히 적는다 — DS 업데이트 때 이 표가 병합 목록이 된다
