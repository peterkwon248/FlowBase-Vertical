# FlowBase 목업 — 핸드오프

작성 2026-08-11 · 대상 Claude Code · 목업 동결 시점 기준

이 문서는 **코드만 읽어서는 알 수 없는 것**만 담는다. 화면 설명은 없다 — 코드가 곧 화면 명세다.
아키텍처(저장소·백엔드·SQLite·batch/connection 체계)는 여기서 다루지 않는다. **구현 헌장 참조.**

### 3-4. React 밖 전역 변수 (주의)

`renderVals()` 첫 줄의 `this.syncAdjust()`가 **모듈 전역을 다시 계산**한다.

```js
let COSTS = {};    // rebuildCosts(state.costAdds)
let ADJUST = {};   // state.adjust
let OPS/FIXED = {} // rebuildOps(state.opsEdit, state.fixedEdit)
let AD_UNALLOC = 0;
ITEMS[].ad         // rebuildAds()가 ITEMS 배열을 직접 변형
```

**`profit()`이 이 전역들을 읽는다.** 즉 순수 함수가 아니다. React 상태 → 전역 → 계산이라는 흐름이라, 실제 구현에서는 `profit(item, context)`로 컨텍스트를 명시 인자로 넘겨야 한다. 특히 `rebuildAds()`는 `ITEMS`의 `ad` 필드를 **제자리에서 덮어쓴다** — 동시성이 생기면 깨진다.

## 4. Claude Design 런타임 의존 목록

### 4-1. 제거 대상

| 의존 | 무엇 | 제거 방법 |
|---|---|---|
| `support.js` | DC 런타임 전체 | 삭제 |

| `renderVals()` | 템플릿에 값 공급 | `render()`로 바꾸고 JSX 반환 |
| `<x-dc>` 래퍼 | 문서 구조 | 삭제 |
| `{{ path }}` 홀 | 값 바인딩 | JSX `{expr}` |
| `<sc-if value>` | 조건부 | `{cond && …}` |
| `<sc-for list as>` | 반복 | `.map()` |

| `$index` | sc-for 인덱스 | `.map((x, i) =>)` |

### 4-2. 변환 시 주의점

**1. `renderVals()`는 매 렌더 전체 재계산이다.** 464건 × 손익 계산 × 화면 전부를 매번 돈다. React로 옮기면 `useMemo`로 쪼개지 않으면 타이핑할 때마다 전체가 다시 계산된다.

**2. 핸들러가 값과 같은 객체에 섞여 있다.** `{ label: "...", pick: () => … }` 형태. JSX로 옮기면 자연스럽게 풀리지만, 지금 구조를 그대로 옮기면 매 렌더 새 함수가 생겨 memo가 안 먹는다.

**3. 클래스 이름은 Vector DS 것이다.** `.db-table`·`.v-btn`·`.nav-item`·`.iconbtn`·`.panel`·`.filterbar`·`.segmented`/`.seg`·`.tab`·`.count`·`.v-chip`·`.v-input`·`.v-menu-item`·`.empty`·`.prop-chip`·`.seg-toggle`·`.st` — 전부 `_ds/.../ui_kits/app/app.css`에 정의돼 있다. **DC 런타임과 무관하므로 그대로 살린다.**

**4. `fb-` 접두 클래스는 우리가 만든 것이다.** `.fb-row`·`.fb-cell`·`.fb-scroll`·`.fb-adj-pop`·`.fb-tabbar`·`.fb-quad-chart`·`.fb-quad-open`·`.fb-quad-full`·`.fb-modal-scrim`·`.fb-head-sub`·`.fb-head-state`·`.fb-head-actions`·`.fb-head-more` — `ds/flowbase-theme.css`에 있다.

**5. `componentDidMount`의 document 리스너**(L3750)는 팝오버 바깥 클릭 처리다. React 그대로 옮겨도 동작하지만 `useEffect` 정리 함수를 빠뜨리면 누수된다.

**6. `window.print()`**(리포트 PDF)와 `document.documentElement.setAttribute("data-theme", …)`(테마)는 DOM 직접 조작이다. DC와 무관하므로 유지.

## 5. 미완·알려진 문제 — 전체 목록

**축소 없이 아는 것을 전부 적는다.**

### 5-1. 중복 코드

1. **내보내기 ⋯ 메뉴 마크업이 5번 복제돼 있다.** 정산·주문·상품·비용·가져오기 기록. 내용은 동일하고 `expSet/expOrd/expPrd/expCst/expSyn`만 다르다. 한 곳을 고치면 다섯 곳을 고쳐야 한다.
2. **확인 모달 본문 구성이 5곳에서 각자 조립된다.** 배치 되돌리기·전체 초기화·연결 해제·페이월·대사 확인. `confirm` 객체 스키마가 암묵적이고 문서화돼 있지 않다.
3. **테마 설정이 두 곳에 있다.** 전역 헤더 토글과 설정 → 일반의 "테마" 행. **서로 연동되지 않는다** — 설정 행은 표시만 하고 실제로 테마를 바꾸지 않는다.

### 5-2. 상태 분열 (같은 개념인데 저장소가 둘)

4. **원가**: `costAdds`(비용 화면, 이력 있음) vs `costQuick`(상품 화면, 이력 없음). 상품 화면에서 넣은 원가는 **원가 이력에 남지 않는다.** §14-2 "변경 이력은 남긴다" 위반.
5. **상품 연결**: `linked`(상품 연결 화면) vs `linkedHere`(주문 화면 인라인). 주문에서 연결해도 상품 연결 화면의 "확인 필요" 개수가 줄지 않는다.
6. **조정**: `adjust`(SKU 상세, 필드별 단일 값) vs `setAdj`(정산 행, 스택 배열). 구조가 다르고 서로 모른다.

### 5-3. 미구현 / 껍데기

7. **파일 선택 버튼이 실제로 파일을 읽지 않는다.** 드롭존·파일 선택 모두 시각적 목업.
8. **URL 가져오기의 검증은 정규식 흉내다** (L5650 부근). `/login|wing\.coupang/` 같은 패턴으로 오류 3종을 분기할 뿐 fetch하지 않는다.
9. **직접 입력 표가 편집되지 않는다.** `manRows`는 고정 배열이고 input에 `onChange`가 없다. "행 추가"·"3건 확정"도 핸들러가 없다.

## 8. §19 반영 — 동결 직전 마지막 수정 (2026-08-11)

**표시(디스플레이) 버튼을 화면 소유로 정정.**

### 8-1. 무엇이 바뀌었나

| 파일 | 위치 | 변경 |
|---|---|---|
| `FlowBase.dc.html` | 템플릿 L255 부근 | 전역 헤더의 표시 버튼을 `<sc-if value="{{ v.dash }}">`로 감쌈 — 대시보드에서만 노출 |

**테마·필터 버튼은 전역 유지.** 필터는 `state.ch`/`state.cat`을 바꾸고 이는 `scopeItems()`를 통해 전 화면 숫자에 반영되므로 전역이 정당하다. 표시 메뉴 내용(레이아웃 3종 + 사이드 카드)은 대시보드에만 영향을 준다.

다른 화면 헤더에는 **자리를 비워 두었다** — placeholder·대체 버튼 없음.

### 8-2. 만들지 않은 것 (LOCK · 구현 단계 이관)

신규 디스플레이 모드는 그리지 않았다. 시드 데이터(정산 5행)로는 검증이 불가능하다.

**허용 매트릭스** — 구현 시 이 범위를 벗어나지 않는다.

| 화면 | 허용 디스플레이 |
|---|---|
| 대시보드 | 레이아웃 3종 (구현됨) |
| 정산 | 시트 + 캘린더 (후속) |
| 주문 | 시트 + 그룹핑 (후속) |
| 상품 연결 · 진단 할 일 | 시트 + 칸반 (후속) |
| 비용 · 상품 | 시트만 |

**LOCK: 사실(Fact) 화면에서 드래그로 상태를 바꾸는 표현은 영구 금지.** 주문·정산의 상태는 마켓이 소유한다. 카드를 끌어 옮기게 하면 화면이 세상을 바꾼 척하게 된다. 칸반은 상태의 주인이 우리인 화면(기준·판단)에만 붙는다 — §6-6·인계 문서 §14 참조.

**디스플레이 선택은 저장된 뷰의 속성에 포함된다** (후속 구현 시). 현재 `curSnap`(로직부 `저장된 뷰` 블록)은 `ch`/`cat`/`from`/`to`/`layout` 5개만 담는다 — 화면별 디스플레이가 생기면 여기에 추가된다.
