# FlowBase — 개발 인계 문서

Claude Design에서 만든 디자인 목업을 실제 앱으로 옮길 때 읽는 문서다.
화면은 `FlowBase.dc.html` 하나에 다 들어 있다.

---

## 1. 이 목업이 무엇이고 무엇이 아닌가

**있는 것 — 앞단.** 15개 화면, 상태 전환, 인터랙션, 손익 계산 로직, Canonical 스키마 설계.
브라우저에서 실제로 눌러볼 수 있고 숫자도 진짜로 다시 계산된다.

**없는 것 — 뒷단.**

| 없는 것 | 지금 상태 |
|---|---|
| 데이터 | 주문 464건이 코드 안에 박힌 시드 |
| 저장 | 새로고침하면 편집 내용이 사라짐 |
| 서버 | 마켓 API를 부를 곳이 없음 |
| 파일 파서 | 가져오기 화면은 있으나 실제로 엑셀을 읽지 않음 |
| 로그인 | 워크스페이스 하나만 존재 |

대략 앞단 30%, 뒷단 70%의 일이 남아 있다.

---

## 2. 절대 깨면 안 되는 규칙 (LOCK)

지시서에서 못 박은 것들이다. 화면이 이 규칙을 전제로 그려져 있다.

**2-1. Core는 마켓을 모른다.**
Profit Engine·Analytics·Dashboard 안에 `if marketplace == "coupang"` 같은 분기를 만들지 않는다.
마켓 분기는 Connector와 Adapter 계층에서 끝난다.

**2-2. Connector와 Adapter를 분리한다.**
Connector는 가져오기만 (인증·호출·페이지네이션·재시도).
Adapter는 변환만 (마켓 응답 → Canonical).
`calculateCoupangProfit()` 같은 마켓별 계산 함수는 만들지 않는다.

**2-3. 모든 행은 `connection_id`를 가진다.**
v1 UI가 마켓당 연결 1개만 보여줘도 이 규칙은 지금부터 적용한다.
이게 없으면 나중에 "쿠팡 2호점"을 지원할 때 기존 데이터를 계정별로 나눌 방법이 없다.

**2-4. 모든 가져오기 행은 `batch_id`를 가진다.**
가져오기는 덮어쓰기가 아니라 append-only 이벤트다.
"8월 8일에 올린 파일만 되돌리기"가 이 규칙 하나로 공짜가 된다.

**2-5. Credential은 평문 저장 금지, 프론트엔드 노출 금지.**
`MarketplaceConnection`에는 참조만 둔다. 실제 값은 로컬 암호화 저장소 또는 서버 Vault.

**2-6. 원본 데이터를 사용자가 덮어쓰지 못한다.**
수정은 Adjustment Layer로 따로 쌓는다. `원본 + 조정 = 표시값`.
그래야 다음 동기화에서 사용자의 수정이 사라지지 않는다.

**2-7. API가 끊겨도 앱은 돈다.**
마켓 장애는 FlowBase 장애가 아니다. 마지막 성공 데이터로 대시보드가 계속 동작한다.

**2-8. CSV/XLSX를 제거하지 않는다.**
파일 가져오기는 API의 하위 기능이 아니라 독립된 공식 Data Source다.

## 3. 데이터 흐름

```
Source (API · CSV · XLSX · Manual)
   ↓
Connector      가져오기만
   ↓
Raw Data       원본 그대로 보관
   ↓
Adapter        마켓별 → Canonical 변환
   ↓
Canonical      Product · SKU · Order · OrderItem · Settlement · Claim · Cost
   ↓
Core           Profit Engine · Analytics
   ↓
View
```

Source는 언제든 바뀐다. Canonical 이후는 바뀌지 않는다.

## 4. 손익 3층 — 이름을 정확히 쓴다

```
매출
 − 할인 · 수수료 · VAT · 배송
 − 매입원가
 − 직접 광고비
 − 운영비 (포장 · 부자재 · 피킹)
= 상품 기여이익        ← 상품별 손익 표의 값
 − 미배분 광고비 (브랜드 검색광고 등)
= 채널 기여이익        ← 특정 채널만 볼 때의 값
 − 고정비 (임대 · 인건 · 창고)
= 회사 순이익          ← 대시보드 상단 큰 숫자
```

상품별 손익을 다 더해도 회사 순이익이 되지 않는다. 그게 정상이고, 화면이 그 차이를 보여준다.

---

## 5. 회사 데이터 vs 마켓 데이터

편집 가능 여부가 여기서 갈린다.

| 종류 | 주인 | 편집 |
|---|---|---|
| 주문 · 정산 · 수수료 · 반품 | 마켓 | 불가 (조정만) |
| 원가 · 광고비 · 운영비 · 고정비 | 회사 | 자유롭게 편집 |
| SKU ↔ 리스팅 매핑 | 회사 | 자유롭게 편집 |
| 앱의 판단 (4사분면 · 액션) | 앱 | 기각 + 이유 기록 |

**원가는 숫자 하나가 아니라 시계열이다.** `SKU.cost = 12000`이 아니라 적용 시작일이 붙은 이력이다.
`costAt(skuId, 주문일)`이 그 주문일 이전 중 가장 늦은 단가를 쓴다.

**광고비는 SKU에 안 붙는다.** 캠페인에 붙고, 캠페인 하나가 여러 SKU를 판다.
배분 규칙 4종: 매출 비례 / 판매량 비례 / 단일 SKU / 배분 안 함(전사).

**고정비는 상품에 배분하지 않는다.** 회사 순이익에서만 뺀다.

## 6. 화면 목록

**현황**
- `dash` 대시보드 — 손익 요약, 상품별·채널별, 일별 캘린더, 리포트 레이아웃
- `settlement` 정산 — 예정·완료·대사
- `products` 상품 — Product → SKU → MarketplaceListing
- `diag` 진단 — 포지셔닝 4사분면 / 광고 효율 / 신규 상품 / 할 일
- `costs` 비용 — 원가 이력 / 광고비 배분 / 운영·고정비 + 손익 3층
- `orders` 주문

**연동**
- `connect` 데이터 연결 — 연결 상태 7종
- `import` 파일 가져오기 — 5단계 위저드
- `sync` 동기화 기록 — 배치 되돌리기

**기준**
- `linking` 상품 연결 — 미매칭 받은편지함
- `fieldmap` 필드 매핑 — 양식(마켓 × 문서 종류)별 열 ↔ Canonical
- `myfields` 내 필드 — 확장 필드 정의

**하단**
- `design` 데이터 구조 — 아키텍처 + ERD (읽기 전용)
- `settings` 설정 — 라이선스 / 일반 / 데이터

## 7. 상태 미리보기

목업에서 상태를 강제로 바꿔볼 수 있는 곳들이다.

| 어디서 | 무엇을 |
|---|---|
| 데이터 연결 → 상태 미리보기 | 연결 상태 7종 (CONNECTED · SYNCING · ERROR · EXPIRED · REAUTH_REQUIRED · DISCONNECTED · FORMAT_CHANGED) |
| 데이터 연결 → 첫 실행 보기 | 온보딩 화면 |
| 설정 → 라이선스 | 무료 / Pro 활성 / 만료 (잠금 상태가 앱 전체에 반영됨) |
| 대시보드 → 표시 | 기본 / 리포트 / 워크벤치 레이아웃 |

## 8. Library — 다음 단계의 핵심

같은 매핑을 사용자마다 다시 만들게 하면 안 된다. 재사용 자산으로 승격시킨다.

```
Library (전역)
├─ 필드 정의      매출 · 수수료 · 정산금액 — 뜻과 형식이 정해진 것
├─ 매핑 프리셋    쿠팡 정산 v2.3 → Canonical
├─ 블록           KPI 카드 · 시계열 · 구성 · 순위표 · 원장 표
└─ 화면 템플릿    정산 대시보드 · 광고 리포트
     ↓ 가져다 쓰기
Workspace
```

**블록은 5종이면 충분하다.** 어떤 데이터가 와도 이 다섯으로 조립된다.

| 블록 | 붙는 조건 |
|---|---|
| KPI 카드 | 숫자 컬럼 하나 |
| 시계열 | 날짜 + 숫자 |
| 구성 (막대·도넛) | 카디널리티 낮은 텍스트 + 숫자 |
| 순위표 | 카테고리 + 숫자 |
| 원장 표 | 나머지 전부 |

이 판정은 규칙으로 한다. AI가 필요하지 않다.

**진짜 자산은 마켓 사전이다.** 마켓별 컬럼 이름 ↔ Canonical 필드.
쿠팡부터 하나씩 쌓는다. 이게 있어야 폐쇄몰·복지몰이 코드 수정 없이 붙는다.

---

## 9. AI가 실제로 필요한 자리

없어도 앱은 돈다. 있으면 편한 곳만 적는다.

- 처음 보는 파일의 컬럼 추측 — 사람이 10개 고를 걸 8개 미리 맞춰줌
- "왜 이번 달 이익이 줄었나" 문장 요약 — 리포트의 코멘트 부분
- 마켓마다 이름이 다른 같은 상품 찾기 — 지금은 문자열 유사도, 여기는 AI가 확실히 낫다

전부 있으면 좋은 것이지 없으면 안 되는 게 아니다. 런타임 AI 없이 만들고 나중에 얹는다.

## 11. v1.5 / v2로 미룬 것

**v1.5** — 같은 마켓 복수 계정 (스키마는 v1에 이미 있음), 마켓 계정 직접 연결(OAuth), 자동 동기화

**v2** — 계정 · 로그인 (카카오·네이버 → 구글 → 애플 순), Workspace(사업자 단위), 자유 시트

자유 시트는 일부러 뒤로 뒀다. 지금 만들면 어떤 표가 필요한지 몰라서 빈 그릇이 된다.
원가·광고비 화면을 쓰다가 "이건 여기 안 들어가네"라고 느낄 때 그 목록이 명세가 된다.

## 11-1. 출시 빌드 전 정리

목업에는 로드맵 라벨이 화면에 노출되어 있다. **출시 빌드에서는 제거하거나 사용자 언어로 치환한다.**

| 목업 표기 | 출시 빌드 |
|---|---|
| `v1.5` | "지원 예정" 또는 완전 숨김 |
| `batch_id` · `connection_id` 같은 내부 키 | 사용자 화면에서는 숨김 (개발자 도구·기록 화면에만) |
| 상태 미리보기 토글 | 제거 (목업 전용) |
| 첫 실행 보기 토글 | 제거 (실제 첫 실행 판정으로 대체) |

## 12. 디자인 시스템

Vector Design System (dark-first, Linear 계열 이슈 트래커 컨벤션).
색·타이포·간격은 전부 토큰(`var(--*)`)을 쓴다. 하드코딩된 hex를 새로 만들지 않는다.

라이트 테마에서 대비가 부족한 의미색만 `ds/flowbase-theme.css`에서 따로 잡아뒀다.
반응형 4단(XL / L / M / S)도 같은 파일에 있다.
