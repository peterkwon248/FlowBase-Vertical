# FlowBase 손익 — 구현 헌장 (지시서 2)

독자: Claude Code. 첨부: 목업 코드 패키지(FlowBase.zip, 동결본) · 핸드오프.md · 인계 문서.md · 픽스처 15개.

**문서 간 충돌 시 우선순위: 이 헌장 > 핸드오프 > 목업 코드.**
목업 코드는 프론트엔드의 완성 기준이다 — 다시 디자인하지 않는다. 이 헌장은 그 밑에 다는 엔진의 규칙이다.

---

## A. 왜 — 변경 불가한 방향 결정

1. **로컬퍼스트, 서버 0대.** 진실은 사용자 기기의 SQLite에 있다. v1에 서버·계정·로그인은 존재하지 않는다. 근거: (a) 속도 — 읽기/쓰기에 네트워크가 끼지 않아야 노션형 비대화를 원천 차단, (b) 신뢰 — "정산 데이터는 당신 컴퓨터 밖으로 나가지 않는다"가 셀링포인트, (c) 비용 — 무료 유저 인프라비 0.
2. **빠름의 두 조건.** ① 진실이 로컬에 있을 것, ② 켤 때 전부 읽지 않을 것. 앱 시작 = 메타데이터만, 화면 진입 = 해당 범위만 쿼리, 집계 = SQL에 위임. 전체 데이터를 메모리(상태)에 올리는 구조 금지.
3. **제품 = 버티컬 단독.** 사용자가 보는 것은 "FlowBase 손익 — 셀러 정산·손익 앱"이다. 제네릭 데이터 보드는 노출하지 않는다. 단, 내부 구조는 Core(도메인 무지) + 도메인 정의(팩 폴더)로 가른다 — B-8 참조.
4. **AI는 액셀러레이터.** AI 없이 모든 기능이 완전 동작한다. AI 호출은 BYOK(사용자 키, 로컬 암호화 저장)이며 Provider 인터페이스 뒤에 둔다. 기존 리포의 서버 AI 라우트는 이 구조로 대체되어 소멸한다(무인증 문제 동시 해소).
5. **정직 원칙.** 조용히 틀린 숫자를 보여주는 것이 최악의 버그다. 읽지 못한 것은 제외하고 제외를 표시한다(FORMAT_CHANGED, "일부 제외" 배지, 미확정 데이터 분리). 실패는 티 나게.

## B. 스키마·데이터 규칙 (LOCK)

1. **모든 사실(Fact) 행 공통 컬럼**: `connection_id`(계정 분리 대비) · `batch_id`(되돌리기 단위) · `library_id`(v1 단일값) · `version` · `updated_at` · `mapping_version`. 첫 마이그레이션부터 존재해야 하며 소급 추가 불가 항목이다.
2. **append-only.** 가져오기는 덮어쓰기가 아니라 batch 추가다. 되돌리기 = 해당 batch 행 제거. `source_key` 기준 중복은 UPSERT.
3. **조정 레이어.** 원본 불변. 수정 = 조정 레코드 추가(이전값·새값·일시·사유). 유효값 = 원본 + 조정 스택. 재가져오기 시 원본만 갱신, 조정 유지. 대사는 원본끼리만 비교 — 조정으로 불일치를 일치로 만들 수 없다. 불일치 해소는 `reconAck`(확인함+사유) 별도 마킹.
4. **데이터 3종 분류** (인계 문서 §14와 동일):
   - **사실**(주문·정산·반품) = 가져오기 경로로만 추가, 인라인 편집 ❌
   - **기준**(원가·상품·연결·매핑·내 필드·비용 룰) = 수동이 기본, 인라인 편집 + 변경 이력
   - **계산**(대시보드·진단·기록) = 입력 영구 ❌
5. **개념당 저장소 하나.** 목업의 상태 분열 3건은 목업의 지름길이며 구현에서 통합한다:
   1. 원가 `costAdds`+`costQuick` → 단일 원가 이력 (상품 화면 빠른 입력도 이력에 남는다)
   2. 상품 연결 `linked`+`linkedHere` → 단일 연결 저장소 (어디서 연결하든 배지 카운트 일치)
   3. 조정 `adjust`+`setAdj` → 단일 조정 스택 모델 (B-3)
6. **매핑 프로파일 = 버전 있는 데이터.** 키 = (마켓, 문서종류, grain). 코드가 아니라 JSON이며 원격(CDN) 갱신 가능. 각 batch는 처리에 쓴 `mapping_version`을 기록한다. 프로파일 변경은 새 버전 생성 — 기존 버전 수정 ❌.
7. **도메인 스키마 = 사전 정의 Table 인스턴스.** 주문/정산/상품 등을 하드코딩 특수 케이스가 아니라 Core Table 엔진 위의 정의된 인스턴스로 구현한다. upstream FlowBase의 `ColumnDef`/`FieldConfig` 어휘를 따른다(핸드오프 github.md 참조). 사용자 정의 테이블 UI는 만들지 않되, 이 구조로 인해 후일 스위치 노출만으로 가능해야 한다.
8. **Core는 마켓을 모른다.** `core/` 안에 쿠팡·네이버·G마켓·옥션·11번가·ESM 문자열 금지. 마켓 지식(프로파일·별칭·감지 규칙)은 `packs/kr-marketplace/` 경계 안에만. Profit Engine에 `if (marketplace === …)` 금지.
9. **Import 파이프라인 6단계** — 모듈 경계와 이름을 이대로:
   `Recognition → Extraction → Normalization → Mapping → Validation → Load`
   - **Recognition**: 매직 바이트 스니핑이 1순위 (`FF FE`→UTF-16 TSV, `<meta`/`<html`→HTML 표, `PK`→xlsx, `D0 CF`→BIFF xls). 확장자는 힌트. 프로파일 후보는 confidence와 함께 복수 반환.
   - **Extraction**: 헤더 행 탐지(상위 ~10행 스캔, 고정 행 번호는 프로파일 힌트일 뿐) · 합계/소계 행 위치 무관 제거 · 시트 분류(데이터 후보/요약) · 시트 단위 채널 배정 허용(한 파일 → 복수 batch).
   - **Normalization**: `"3,000원"→3000`, `"12.4%"→0.124`, `"-"/""→null`, 날짜 4종, ragged row 패딩. cp949/utf-8/utf-16 인코딩 감지.
   - **Validation**: 필수 필드·타입·키 존재·파싱 성공률·행 수 이상. 오류 행은 제외하되 사유와 함께 표시, 내려받기 가능.
   - **스트리밍은 v1이다.** 80,138행×43열 파일이 매월 정기 입력이다. 전체 메모리 적재 금지 — 청크→SQLite. 미리보기(앞 N행)와 전체 파싱을 분리.
10. **티어**: 무료 = 채널 1 · 파일/URL/직접 입력 · 저장된 뷰 2 / Pro ₩9,900 = 전 채널 · 월간 리포트(+PDF) · 뷰 무제한 · 양식 자동 업데이트. **내보내기(XLSX/CSV)는 무료 전면 개방 — 데이터 인질 금지, LOCK.** 다운그레이드 시 기존 뷰·데이터 삭제 ❌, 신규 저장만 차단. 라이선스 = 로컬 키 검증, 결제는 외부 링크.
11. **자격증명**: 마켓 API 키·BYOK 키는 로컬 암호화 저장(vault). 우리 서버 전송 ❌ (서버가 없다).

## C. 접합 규칙 — 목업을 실제 앱으로

1. **몸체 보존.** 목업의 화면·마크업·토큰·카피는 기준이다. DC 런타임 제거와 데이터 주입부 교체 외 임의 변경 금지. 제거 절차와 주의점은 핸드오프 §4를 따른다(특히: `renderVals` 전량 재계산 → `useMemo` 분할, Vector DS 클래스는 유지, `fb-` 클래스는 우리 것).
2. **시드 경계 = 핸드오프 §2 목록이 전부다.** 시드 상수·생성기·인라인 시드를 리포지토리 인터페이스로 교체한다. `profit()`은 전역(COSTS/ADJUST/OPS/FIXED/AD_UNALLOC) 의존을 제거하고 `profit(item, context)` 명시 인자로 — `rebuildAds()`의 ITEMS 제자리 변형도 제거.
3. **목업 must-fix** (알려진 결함 — 재현 금지, 수정하며 이식):
   - B-5의 상태 분열 3건 통합
   - 핸드오프 이슈 23: 진단 안내문("신규 상품 제외")과 실제 집계 불일치 — 4사분면·포지셔닝 집계에서 `NEW_SEED` 상품 실제 제외
   - 이슈 20: 고정비 안분 8/31 고정 → 조회 기간 기준으로
   - 이슈 22: 진단 ROAS와 대시보드 광고비의 기간 불일치 → 동일 기간 스코프 함수 공유
   - 이슈 19: 대사 하드코딩(`gmarket||naver`) → 실제 원본 대 원본 비교 로직
   - 이슈 3: 테마 설정 이중화 → 단일 소스 연동
   - 이슈 21: `"2026-"` 연도 하드코딩 제거, 이슈 41: "오늘" 고정 제거
4. **출시 빌드 정리**: `v1.5`/`지원 예정` 내부 라벨 치환, `batch_id`·`connection_id` 사용자 화면 노출 제거(내부 키는 툴팁/개발자 영역으로), 상태 미리보기·첫 실행 토글 제거, 죽은 코드(`skuCostSeedRun`, `adOvD`, `cacAvgN`, `RichTooltip.jsx`) 삭제.
5. **§18 구현**(디자인은 기존 위저드 패턴 재사용, 신규 시각 요소 발명 금지): 멀티시트 시트 선택 단계 · 제외 행 삭선+카운트 · 판정 후보 복수+일치도 · 파일 정체 고지 · 대용량 진행(미리보기 즉시/전체 배경).
6. **디스플레이 허용 매트릭스**(핸드오프 §8-2, LOCK): 대시보드 = 레이아웃 3종 / 정산 = 시트+캘린더(후속) / 주문 = 시트+그룹핑(후속) / 상품 연결·진단 할 일 = 시트+칸반(후속) / 비용·상품 = 시트만. **Fact 화면 드래그 상태 변경 영구 금지.** 디스플레이 선택 구현 시 `curSnap`(저장된 뷰 스냅샷)에 필드 추가.
7. **새 실패 상태 발명 금지.** 파싱 오류·DB 오류 등 목업에 없는 실패는 기존 상태 체계(ERROR/FORMAT_CHANGED/오류 행 제외)에 편입한다.
8. **기존 리포(peterkwon248/FlowBase)에서 이식**: formula parser/evaluator/cycles(테스트 포함) · 파서(단, CSV 멀티라인 quoted 셀 버그를 문자 단위 상태머신으로 수정 후 사용) · 차트 컴포넌트 · SavedView 모델 · import-normalizers.
   **이식 금지**: 제네릭 보드 UI 셸, Wiki, Library 카탈로그, localStorage persist 구조, 서버 AI 라우트.

## D. 세션 계획 — 스코프와 합격 기준

- **세션 1 — 파이프라인 (UI 없음).** 포맷 스니퍼 + 파서 4종(xlsx 스트리밍·BIFF xls·HTML 표·구분자+인코딩) + Extraction + Normalization + 픽스처 하네스.
  **합격**: 픽스처 15개 전부 `expectedProfile`/`expectedSheets`/`expectedHeader`/`expectedRowCount` 통과.
  **선행 작업**: 픽스처 비식별화(구매자명·연락처·주소 치환) 후 테스트 저장소에 넣는다 — 원본 그대로 커밋 금지.
- **세션 2 — 저장 골격.** Tauri + SQLite, B부 스키마 전부, append-only batch, 리포지토리 계층, "활성 데이터만 로드" 쿼리 패턴, 조정·대사 저장 모델.
  **합격**: 세션 1 파이프라인 출력이 batch로 적재되고 되돌리기가 작동.
- **세션 3 — 접합.** 목업 몸체 이식(C부), 시드→리포지토리 교체, 실파일(사용자의 7월 정산·광고 파일) 통과, 손익 숫자를 사용자 손계산 정답지와 원 단위 대조.
  **합격**: 정답지 일치 또는 차이의 원인 규명.

각 세션은 독립적으로 검증 가능해야 하며, 전체 리팩터링을 한 세션에 일괄 위임하지 않는다.

## E. 금지 목록

1. 목업 디자인 임의 변경, 새 화면·새 시각 요소 발명
2. 사실(Fact) 행 인라인 편집 UI — 수정은 조정 레이어로만
3. 조용한 실패 — 읽기 실패·부분 데이터를 표시 없이 넘기는 것
4. 마켓 이름의 `core/` 침투, Profit Engine 마켓 분기
5. localStorage 통짜 저장, 시작 시 전체 데이터 메모리 적재
6. 팩 엔진·`.flowpack`·사용자 정의 테이블 UI·로그인·동기화·마켓플레이스 선제 구현 (경계만 유지: B-7·B-8)
7. "동기화"라는 카피 — 양방향·자동이 실존하기 전까지 (용어: 연결/가져오기/batch)
8. 내보내기·기본 기능의 유료 잠금 추가 (티어는 B-10이 전부)
9. AI를 필수 경로에 두는 것 — AI 꺼져도 전 기능 동작
10. 픽스처 원본(실명 포함) 커밋
